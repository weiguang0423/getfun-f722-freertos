## 2. IMX335摄像头

媒体拓扑确认传感器为`m00_b_imx335 4-001a`，节点为`/dev/v4l-subdev3`；经过RKISP后，
主采集节点为`/dev/video0`。传感器链路为`SRGGB10_1X10`、2616×1964、30 fps；RKISP主路径
支持NV12等格式，最大2592×1944。

本次短采集命令：

```sh
v4l2-ctl -d /dev/video0 \
  --set-fmt-video=width=800,height=600,pixelformat=NV12 \
  --stream-mmap=3 --stream-count=300 --stream-to=/dev/null
```

实测结果：300帧持续显示`30.00 fps`，`CAMERA_RC=0`；启动诊断为
`tx stream:4 lose frame:0`，随后正常停流。按开发者要求不执行30分钟稳定性测试。最终曝光参数、
镜像策略和安装方向依赖实际机体安装，在S7.4实时链开始前冻结，不能由本次桌面短采集代签。

## 4. 最小程序与实测输出

最小程序为[`Linux/RK3568/s7_1_rknn_smoke.c`](../Linux/RK3568/s7_1_rknn_smoke.c)。它只完成模型加载、张量
查询、全零固定输入、NPU执行、浮点输出提取和逐次FNV-1a哈希比较，不加入图像分类后处理或
额外框架。SDK交叉编译器为：

```text
/home/user123/rk3568_sdk/buildroot/output/rockchip_rk3568/host/bin/aarch64-buildroot-linux-gnu-gcc
```

源码已使用`-std=c11 -Wall -Wextra -Werror -O2`和SDK内RK356X的`rknn_api.h`、AArch64
`librknnrt.so`完成交叉构建检查。板端测试二进制SHA-256为
`d7991c03e1c4a01d44dbb07590895e874661aa08eb9e53ddb3b592648a0a30e0`。

板端命令：

```sh
/tmp/s7_1/s7_1_rknn_smoke /tmp/s7_1/s7_1_mobilenet_v1.rknn 10
```

## 5. 恢复与后续边界

1. 重启后通过COM8连接；若停在FIQ `debug>`，输入`console`返回Linux shell。
2. 用`v4l2-ctl --list-devices`和`media-ctl -p`重新确认IMX335及`/dev/video0`。
3. 用`cat /sys/module/rknpu/version`和`sha256sum /usr/lib/librknnrt.so`复核NPU环境。
4. 从SDK原路径重新复制官方RK356X模型，并核对本文件记录的SHA-256。
5. 重新交叉构建最小程序，复制到`/tmp/s7_1`后执行第4节命令。

S7.1不安装或升级Toolkit2、Runtime、驱动，也不把测试产物做成开机服务。S7.2已按文档36固定
手部模型、PC参考链与测试集；S7.3再固定Toolkit2版本、重新转换手部模型并做板端误差/性能验收。
S7.4仍须完成摄像头实时推理链的30分钟稳定性关口，本次豁免不能沿用。
