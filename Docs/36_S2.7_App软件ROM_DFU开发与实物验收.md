# S2.7 App软件ROM DFU开发与实物验收

> 当前状态：✅ 软件与真实板卡DFU枚举、恢复烧录验收通过
> 安全要求：全程拆桨；S1.10～S1.12与本实物关口全部关闭前不进入S5

## 1. 固定来源与接口

- STM32官方AN2606 Rev 70第44节：STM32F72xxx/73xxx System Memory从
  `0x1FF00000`开始，ROM Bootloader支持USB OTG FS的PA11/PA12。
- Betaflight标准`MSP_REBOOT`命令号为68，模式1为
  `MSP_REBOOT_BOOTLOADER_ROM`；成功响应回显模式1。
- 本项目只实现ROM DFU模式，不实现普通重启、MSC或Flash Bootloader，不新增CLI和RTOS任务。

## 2. 软件行为

```text
App发送 MSP_REBOOT(68), payload=[1]
  -> MspTask读取一致状态快照
  -> 拒绝Armed / ARM请求 / Motor Test / 系统故障 / 非法或重复请求
  -> 关闭Configurator解锁许可，取消未提交配置事务
  -> 回送成功帧，payload=[1]
  -> USB CDC发送完成后停止并反初始化USB
  -> DShot与Motor 1～8强制安全低电平
  -> 在NOLOAD RAM写入magic及反码，执行系统复位
  -> main()最早期消费并清除一次性请求
  -> 设置ROM向量表和MSP，跳转0x1FF00000向量入口
  -> ROM Bootloader枚举USB DFU
```

一次性请求不写用户Flash和参数槽。意外上电、普通复位或magic/反码不匹配时正常启动应用，
不会进入DFU；请求在跳转前清除，ROM异常返回或再次复位也不会形成DFU重启循环。
