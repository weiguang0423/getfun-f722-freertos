## 1. 基本原则

本项目不建立复杂测试流程，但每次调试至少做到：

1. 明确这次只验证什么。
2. 修改前保留可恢复固件。
3. 电机和控制测试默认拆桨。
4. 先观察数据，再接入控制输出。
5. 出现异常时记录现象、原因和最后结论。
6. 同一次测试尽量只修改一个主要变量。

## 2. 每次开发前检查

### 2.1 源码和构建

- 当前 Git 分支和提交明确。
- `config.h` 未被意外覆盖。
- 编译器版本正确。
- 构建无错误。
- 保存新的 HEX、ELF 和 MAP。
- 记录固件版本或构建时间。

### 2.2 烧录前

- 螺旋桨已拆除。
- 电池已断开，除非测试明确需要电池供电。
- BOOT/DFU 恢复方法可用。
- 原厂恢复 HEX 仍在安全位置。
- USB 线、电源和飞控连接可靠。

### 2.3 烧录后

先执行：

```text
version
status
tasks
```

检查：

- 固件版本是本次构建。
- MCU 和时钟正确。
- FreeRTOS 任务均在运行。
- 没有持续重启。
- 没有异常高 CPU 占用。
- 电机保持停止。

## 3. 最小系统调试

### 3.1 UART 日志

检查内容：

- 上电后立即有启动日志。
- 能看到固件版本。
- 能看到时钟初始化结果。
- 能看到任务启动结果。
- 设备初始化失败时有明确提示。

UART4 接线以硬件基线为准，使用 3.3 V USB-TTL，不连接 TTL 电源脚给飞控供电。

### 3.2 FreeRTOS

检查：

- `ImuTask`、`FlightTask`、`RcTask`、`MspTask` 能启动。
- 空闲任务能够运行。
- 任务栈没有快速耗尽。
- 1 kHz FlightTask 计数稳定增加。
- USB 查询不会明显阻塞 FlightTask。

第一版只需连续运行约 30 分钟观察是否重启、卡死或任务停止，不要求复杂压力报告。

### 3.3 USB 和 DFU

检查：

- Windows 出现正常 COM 口。
- Betaflight App 可以连接。
- App 可以显示版本和状态。
- CLI 可以进入和退出。
- 可以请求重启。
- 可以进入 STM32 ROM DFU。

## 4. ICM42688P 与姿态调试

### 4.1 原始数据

在 App Setup/Sensors 或 CLI 中观察：

- Gyro 三轴持续变化。
- Accel 三轴持续变化。
- 静止时数据没有明显跳变。
- 时间戳和样本计数持续增加。
- SPI 错误计数不持续增加。

### 4.2 轴向检查

按固定动作测试：

1. 飞控水平静止。
2. 机头向下。
3. 机头向上。
4. 机体向右倾斜。
5. 机体向左倾斜。
6. 顺时针转动。
7. 逆时针转动。

记录每个动作对应的 Gyro、Accel 和 App 三维模型方向。

### 4.3 校准

- Gyro 校准时飞控保持静止。
- 校准完成后静止角速度接近零。
- 水平放置后 Roll/Pitch 接近零。
- 加速度计校准结果可以保存并在重启后加载。

### 4.4 姿态估计

- 缓慢倾斜时 App 模型方向一致。
- 快速运动后没有明显发散。
- 回到水平后 Roll/Pitch 能够回归。
- 静止时 Yaw 允许缓慢漂移。

通过这些检查后，才进入闭环控制方向测试。

## 5. CRSF 接收机调试

### 5.1 接线与串口

按冻结基线连接 UART2：

```text
CR8 TX → PA3 / RX2
CR8 RX ← PA2 / TX2
```

### 5.2 App Receiver 页面

检查：

- Roll 通道正确。
- Pitch 通道正确。
- Yaw 通道正确。
- Throttle 通道正确。
- AUX 开关正确。
- 中点和端点合理。
- LQ/RSSI 状态更新。

### 5.3 Failsafe

拆桨状态下：

1. 保持飞控和接收机正常连接。
2. 关闭遥控器或断开接收机信号。
3. 确认飞控进入 Failsafe。
4. 确认逻辑电机值归零。
5. 恢复连接。
6. 确认飞控不会自动重新 ARM。

## 6. ADC、电池和板载功能

### 6.1 VBAT

使用万用表测量真实电池电压，与 App 显示比较。

调节电压比例，直到常用电压范围内误差可以接受。将最终比例更新到硬件基线。

### 6.2 Current

在有已知负载或可靠电流表时标定：

- 零电流偏置。
- 电流比例。
- 低电流和较高电流下的误差。

没有可靠参考仪表时，不要把当前比例写成已确认值。

### 6.3 LED、蜂鸣器和 PINIO

逐项测试：

- LED0
- LED1
- LED Strip
- Buzzer
- PINIO1
- PINIO2

记录实际有效电平和对应外部功能。

## 7. Betaflight App 页面检查

每实现一个 MSP 模块，就检查对应页面，不等所有功能完成后再一次处理。

### Setup

- 固件身份正确。
- 板名正确。
- 传感器状态正确。
- 三维姿态正确。
- 电池信息正确。
- 解锁禁止原因可理解。

### Ports

- UART1～UART6 显示正确。
- UART2 可以设置 Serial RX。
- 设置保存并重启后仍有效。

### Configuration

- Quad-X 正确。
- CRSF 正确。
- DShot300 正确。
- ADC meter 正确。
- 不支持的功能不会导致页面报错或断连。

### Receiver

- 通道、端点和开关正确。
- Channel Map 可以保存。
- Failsafe 状态正确。

### Modes

- ARM 范围可设置。
- ANGLE 范围可设置。
- 模式状态实时变化。

### PID Tuning

- Roll/Pitch/Yaw PID 可读写。
- Angle 参数可读写。
- Rates 和 Expo 可读写。
- `save` 后重启参数仍存在。

### Motors

- Motor 1～4 当前值正确。
- Armed 时 App 测试被拒绝。
- App 测试断开后电机归零。

### OSD 与 Blackbox

基础飞行后检查：

- OSD 元素位置和视频制式。
- MAX7456 实际画面。
- Flash 状态和擦除。
- Blackbox 日志写入和读取。

## 8. DShot 无桨测试

### 8.1 逻辑信号

先不连接真实电机，使用逻辑分析仪检查：

- DShot300 帧频率。
- 0/1 高电平时间。
- 16 位帧长度。
- Checksum。
- 停止命令。

### 8.2 单电机

拆除所有螺旋桨：

1. 只测试 Motor 1。
2. 从很低测试值开始。
3. 确认 App 断开后停止。
4. 依次测试 Motor 2～4。

### 8.3 电机编号

建立实际机架图并记录：

```text
             机头
              ↑

       [待确认]   [待确认]

       [待确认]   [待确认]
```

在实际测试完成前，不在文档中猜测 Motor 1～4 的物理位置。

### 8.4 旋转方向

记录每个电机：

- 物理位置
- Betaflight/App 编号
- CW 或 CCW
- 是否需要在 ESC 中反向

完成后更新硬件冻结文档。

## 9. 控制方向无桨测试

不接螺旋桨，保持低测试输出或仅观察逻辑电机值。

### Roll

- 向右倾斜机体。
- 控制器应该产生把机体推回左侧的修正。
- 检查左右电机变化关系。

### Pitch

- 机头向下。
- 控制器应该产生抬起机头的修正。
- 检查前后电机变化关系。

### Yaw

- 手动顺时针转动。
- 控制器应该生成反向 Yaw 修正。
- 检查 CW/CCW 电机变化关系。

任何一轴方向错误，都先检查传感器轴、姿态符号、PID 误差和 Mixer，不通过调换随机电机来掩盖问题。

- [ ] 测试场地空旷且远离人员。

## 11. 首飞顺序

### 11.1 第一次：贴地短时测试

- 使用 Rate 模式。
- 缓慢增加油门。
- 观察是否有翻转趋势。
- 一旦方向异常立即 DISARM。
- 不进行大动作。

如果起飞瞬间翻转，优先检查：

1. 电机编号。
2. 螺旋桨方向。
3. 电机旋转方向。
4. Gyro 方向。
5. Mixer 符号。

### 11.2 第二次：短时悬停

- 低空悬停数秒。
- 检查 Roll/Pitch/Yaw 操纵方向。
- 检查明显振荡或漂移。
- 降落后检查电机和 ESC 温度。

### 11.3 第三次：Rate 调整

- 延长悬停时间。
- 做小幅 Roll/Pitch/Yaw 输入。
- 调整 P、I、D。
- 每次只修改少量参数。

### 11.4 Angle 模式

Rate 模式基本正常后再测试 Angle：

- 确认模式开关有效。
- 小角度倾斜。
- 检查回中后的自动水平。
- 调整 Angle P 和最大倾角。

## 12. 常见问题检查顺序

### App 连接失败

1. USB 是否枚举。
2. COM 口是否正确。
3. MSP API 和消息长度。
4. MspTask 是否运行。
5. 是否在 CLI 模式。

### IMU 无数据

1. SPI1 引脚和 CS。
2. WHO_AM_I。
3. SPI mode 和频率。
4. 数据就绪或读取周期。
5. DMA/Cache。

### Receiver 无通道

1. TX/RX 是否交叉。
2. UART2 是否为 420000 baud。
3. CRSF 帧长度和 CRC。
4. 接收机是否已绑定。

### 电机不转

1. ESC 是否供电。
2. DShot 波形。
3. Motor 引脚。
4. 是否处于允许测试状态。
5. DShot 值是否在有效范围。

### 起飞翻转

1. 电机位置。
2. 电机旋转方向。
3. 螺旋桨方向。
4. 姿态轴向。
5. Mixer 方向。

### 高频振荡

1. P/D 是否过高。
2. Gyro 噪声。
3. 滤波。
4. 机架或电机机械振动。
5. 控制周期和 `dt`。

## 16. 2026-07-27：ICM42688P 1 kHz轮询软件基线

### 目标

在 `v0.1.0-platform-baseline` 上建立SPI1、ICM42688P、ImuTask、app_state和
Betaflight `MSP_RAW_IMU`的完整软件链路，实物测试由开发者后续执行。

### 修改

- SPI1：PA5/PA6/PA7，PA4软件CS，Mode 0，1.6875 MHz。
- ICM42688P：复位、`WHO_AM_I=0x47`、1 kHz、±2000 dps、±16 g、配置回读。
- ImuTask：静态512 words、idle+4、Data Ready轮询、SI单位、`CW90_DEG`。
- app_state：完整IMU快照、统计和局部故障恢复。
- MSP：真实ACC/GYRO缩放、在线位和离线清零。
- 诊断：低优先级InitTask每秒输出IMU摘要。

### 软件结果

- Debug：RAM 38,408 B，FLASH 64,228 B。
- Release：RAM 38,392 B，FLASH 36,100 B。
- Debug和Release均构建通过；`git diff --check`通过。

### 结论

- 软件交付完成。
- 开发者于2026-07-27确认WHO_AM_I、SPI波形、方向、1 kHz、30分钟稳定性、
  故障恢复、Betaflight App和电机安全状态全部通过。
- 满足创建`v0.2.0-imu-polling-baseline`的条件。

## 17. 2026-07-27：ICM42688P DMA与DRDY门控软件基线

### 目标

在 `v0.2.0-imu-polling-baseline` 上将稳定运行阶段的14字节样本读取升级为
SPI1 DMA，同时保持已经验收的量程、ODR、SI单位、`CW90_DEG`和MSP结果不变。

### 硬件边界

- 原始GETFUNF722V3目标没有定义 `GYRO_1_EXTI_PIN`。
- PC4已定义为PINIO1，不能猜作IMU中断。
- 本版使用1 kHz绝对周期阻塞读取 `INT_STATUS.DATA_RDY_INT`，就绪后才启动DMA。
- 本版名称中的DRDY表示数据就绪门控，不表示已经实现GPIO EXTI。

### 修改

- SPI1 RX：DMA2 Stream 0 / Channel 3。
- SPI1 TX：DMA2 Stream 3 / Channel 3。
- DMA IRQ：抢占优先级5，允许调用 `vTaskNotifyGiveFromISR()`。
- `imu_bus`：两个32字节对齐静态槽位、异步start/finish/abort、条件式Cache维护。
- `icm42688p`：DMA样本启动和14字节大端解析接口。
- ImuTask：DMA完成通知、2 ms超时、连续三次失败重初始化。
- app_state与1 Hz诊断：增加DRDY轮询、DMA成功、启动错误、完成错误、超时和abort计数。

### 软件结果

- Debug与Release构建结果见 `10_v0.3.0_IMU_DMA与DRDY软件交付与实物验收.md`。
- DMA缓冲区地址、静态检查和MSP/Motor回归结果同样记录在 `10`。

### 结论

- 软件开发完成后进入实物验收。
- 实物验收前不创建 `v0.3.0-imu-dma-drdy-baseline` 标签。
