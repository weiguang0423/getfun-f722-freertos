## 1. 基本原则

本项目不建立复杂测试流程，但每次调试至少做到：

1. 明确这次只验证什么。
2. 修改前保留可恢复固件。
3. 电机和控制测试默认拆桨。
4. 先观察数据，再接入控制输出。
5. 出现异常时记录现象、原因和最后结论。
6. 同一次测试尽量只修改一个主要变量。

## 2. 每次开发前检查

### 2.1 源码和构建

- 当前 Git 分支和提交明确。
- `config.h` 未被意外覆盖。
- 编译器版本正确。
- 构建无错误。
- 保存新的 HEX、ELF 和 MAP。
- 记录固件版本或构建时间。

### 2.2 烧录前

- 螺旋桨已拆除。
- 电池已断开，除非测试明确需要电池供电。
- BOOT/DFU 恢复方法可用。
- 原厂恢复 HEX 仍在安全位置。
- USB 线、电源和飞控连接可靠。

### 2.3 烧录后

先执行：

```text
version
status
tasks
```

检查：

- 固件版本是本次构建。
- MCU 和时钟正确。
- FreeRTOS 任务均在运行。
- 没有持续重启。
- 没有异常高 CPU 占用。
- 电机保持停止。

## 3. 最小系统调试

### 3.1 UART 日志

检查内容：

- 上电后立即有启动日志。
- 能看到固件版本。
- 能看到时钟初始化结果。
- 能看到任务启动结果。
- 设备初始化失败时有明确提示。

UART4 接线以硬件基线为准，使用 3.3 V USB-TTL，不连接 TTL 电源脚给飞控供电。

### 3.2 FreeRTOS

检查：

- `ImuTask`、`FlightTask`、`RcTask`、`MspTask` 能启动。
- 空闲任务能够运行。
- 任务栈没有快速耗尽。
- 1 kHz FlightTask 计数稳定增加。
- USB 查询不会明显阻塞 FlightTask。

第一版只需连续运行约 30 分钟观察是否重启、卡死或任务停止，不要求复杂压力报告。

### 3.3 USB 和 DFU

检查：

- Windows 出现正常 COM 口。
- Betaflight App 可以连接。
- App 可以显示版本和状态。
- CLI 可以进入和退出。
- 可以请求重启。
- 可以进入 STM32 ROM DFU。

## 4. ICM42688P 与姿态调试

### 4.1 原始数据

在 App Setup/Sensors 或 CLI 中观察：

- Gyro 三轴持续变化。
- Accel 三轴持续变化。
- 静止时数据没有明显跳变。
- 时间戳和样本计数持续增加。
- SPI 错误计数不持续增加。

### 4.2 轴向检查

按固定动作测试：

1. 飞控水平静止。
2. 机头向下。
3. 机头向上。
4. 机体向右倾斜。
5. 机体向左倾斜。
6. 顺时针转动。
7. 逆时针转动。

记录每个动作对应的 Gyro、Accel 和 App 三维模型方向。

### 4.3 校准

- Gyro 校准时飞控保持静止。
- 校准完成后静止角速度接近零。
- 水平放置后 Roll/Pitch 接近零。
- 加速度计校准结果可以保存并在重启后加载。

### 4.4 姿态估计

- 缓慢倾斜时 App 模型方向一致。
- 快速运动后没有明显发散。
- 回到水平后 Roll/Pitch 能够回归。
- 静止时 Yaw 允许缓慢漂移。

通过这些检查后，才进入闭环控制方向测试。

## 5. CRSF 接收机调试

### 5.1 接线与串口

按冻结基线连接 UART2：

```text
CR8 TX → PA3 / RX2
CR8 RX ← PA2 / TX2
```

### 5.2 App Receiver 页面

检查：

- Roll 通道正确。
- Pitch 通道正确。
- Yaw 通道正确。
- Throttle 通道正确。
- AUX 开关正确。
- 中点和端点合理。
- LQ/RSSI 状态更新。

### 5.3 Failsafe

拆桨状态下：

1. 保持飞控和接收机正常连接。
2. 关闭遥控器或断开接收机信号。
3. 确认飞控进入 Failsafe。
4. 确认逻辑电机值归零。
5. 恢复连接。
6. 确认飞控不会自动重新 ARM。

## 8. DShot 无桨测试

### 8.1 逻辑信号

先不连接真实电机，使用逻辑分析仪检查：

- DShot300 帧频率。
- 0/1 高电平时间。
- 16 位帧长度。
- Checksum。
- 停止命令。

### 8.2 单电机

拆除所有螺旋桨：

1. 只测试 Motor 1。
2. 从很低测试值开始。
3. 确认 App 断开后停止。
4. 依次测试 Motor 2～4。

### 8.3 电机编号

建立实际机架图并记录：

```text
             机头
              ↑

       [待确认]   [待确认]

       [待确认]   [待确认]
```

在实际测试完成前，不在文档中猜测 Motor 1～4 的物理位置。

### 8.4 旋转方向

记录每个电机：

- 物理位置
- Betaflight/App 编号
- CW 或 CCW
- 是否需要在 ESC 中反向

完成后更新硬件冻结文档。

## 9. 控制方向无桨测试

不接螺旋桨，保持低测试输出或仅观察逻辑电机值。

### Roll

- 向右倾斜机体。
- 控制器应该产生把机体推回左侧的修正。
- 检查左右电机变化关系。

### Pitch

- 机头向下。
- 控制器应该产生抬起机头的修正。
- 检查前后电机变化关系。

### Yaw

- 手动顺时针转动。
- 控制器应该生成反向 Yaw 修正。
- 检查 CW/CCW 电机变化关系。

任何一轴方向错误，都先检查传感器轴、姿态符号、PID 误差和 Mixer，不通过调换随机电机来掩盖问题。

## 11. 首飞顺序

### 11.1 第一次：贴地短时测试

- 使用 Rate 模式。
- 缓慢增加油门。
- 观察是否有翻转趋势。
- 一旦方向异常立即 DISARM。
- 不进行大动作。

如果起飞瞬间翻转，优先检查：

1. 电机编号。
2. 螺旋桨方向。
3. 电机旋转方向。
4. Gyro 方向。
5. Mixer 符号。

### 11.2 第二次：短时悬停

- 低空悬停数秒。
- 检查 Roll/Pitch/Yaw 操纵方向。
- 检查明显振荡或漂移。
- 降落后检查电机和 ESC 温度。

### 11.3 第三次：Rate 调整

- 延长悬停时间。
- 做小幅 Roll/Pitch/Yaw 输入。
- 调整 P、I、D。
- 每次只修改少量参数。

### 11.4 Angle 模式

Rate 模式基本正常后再测试 Angle：

- 确认模式开关有效。
- 小角度倾斜。
- 检查回中后的自动水平。
- 调整 Angle P 和最大倾角。

## 12. 常见问题检查顺序

### App 连接失败

1. USB 是否枚举。
2. COM 口是否正确。
3. MSP API 和消息长度。
4. MspTask 是否运行。
5. 是否在 CLI 模式。

### IMU 无数据

1. SPI1 引脚和 CS。
2. WHO_AM_I。
3. SPI mode 和频率。
4. 数据就绪或读取周期。
5. DMA/Cache。

### Receiver 无通道

1. TX/RX 是否交叉。
2. UART2 是否为 420000 baud。
3. CRSF 帧长度和 CRC。
4. 接收机是否已绑定。

### 电机不转

1. ESC 是否供电。
2. DShot 波形。
3. Motor 引脚。
4. 是否处于允许测试状态。
5. DShot 值是否在有效范围。

### 起飞翻转

1. 电机位置。
2. 电机旋转方向。
3. 螺旋桨方向。
4. 姿态轴向。
5. Mixer 方向。

### 高频振荡

1. P/D 是否过高。
2. Gyro 噪声。
3. 滤波。
4. 机架或电机机械振动。
5. 控制周期和 `dt`。

## 17. 2026-07-27：ICM42688P DMA与DRDY门控软件基线

### 目标

在 `v0.2.0-imu-polling-baseline` 上将稳定运行阶段的14字节样本读取升级为
SPI1 DMA，同时保持已经验收的量程、ODR、SI单位、`CW90_DEG`和MSP结果不变。

### 硬件边界

- 原始GETFUNF722V3目标没有定义 `GYRO_1_EXTI_PIN`。
- PC4已定义为PINIO1，不能猜作IMU中断。
- 本版使用1 kHz绝对周期阻塞读取 `INT_STATUS.DATA_RDY_INT`，就绪后才启动DMA。
- 本版名称中的DRDY表示数据就绪门控，不表示已经实现GPIO EXTI。

### 修改

- SPI1 RX：DMA2 Stream 0 / Channel 3。
- SPI1 TX：DMA2 Stream 3 / Channel 3。
- DMA IRQ：抢占优先级5，允许调用 `vTaskNotifyGiveFromISR()`。
- `imu_bus`：两个32字节对齐静态槽位、异步start/finish/abort、条件式Cache维护。
- `icm42688p`：DMA样本启动和14字节大端解析接口。
- ImuTask：DMA完成通知、2 ms超时、连续三次失败重初始化。
- app_state与1 Hz诊断：增加DRDY轮询、DMA成功、启动错误、完成错误、超时和abort计数。

### 软件结果

- Debug与Release构建结果见 `10_v0.3.0_IMU_DMA与DRDY软件交付与实物验收.md`。
- DMA缓冲区地址、静态检查和MSP/Motor回归结果同样记录在 `10`。

### 结论

- 开发者于2026-07-27确认发布，目标标签已经创建并推送。
- v0.3.0冻结后进入陀螺静态零偏校准。

## 18. 2026-07-29：陀螺静态零偏校准软件基线

### 目标

在 `v0.3.0-imu-dma-drdy-baseline` 上加入上电静态零偏校准，在姿态和控制功能开始前
建立可靠的机体系角速度输入与解锁抑制状态。

### 修改

- 新增纯算法模块 `gyro_calibration`，不依赖HAL或FreeRTOS。
- 连续250样本预热、2000样本Welford均值/方差。
- 5 deg/s瞬时角速度、0.8 g～1.2 g加速度模长和0.5 deg/s标准差门限。
- 校准位于SI换算和 `CW90` 之后，READY后冻结并扣除三轴机体系零偏。
- IMU离线清除校准状态，完整恢复后自动重新校准。
- app_state增加校准状态、进度、统计、零偏和独立解锁抑制位。
- UART 1 Hz摘要增加校准可观测性；MSP缩放和v0.3.0 DMA链不变。

### 软件结果

- Debug：RAM 39,008 B，FLASH 73,012 B。
- Release：RAM 39,008 B，FLASH 41,120 B。
- Debug和Release均构建通过；`git diff --check`通过。
- 详细设计见 `11_v0.4.0_陀螺静态零偏校准开发计划.md`。
- 软件交付和实物验收表见
  `12_v0.4.0_陀螺静态零偏校准软件交付与实物验收.md`。

### 结论

- 开发者于2026-07-30确认静止启动、运动拒绝、残差、重启/恢复、DMA/MSP回归、
  30分钟稳定性和Motor安全全部通过。
- 满足创建 `v0.4.0-gyro-calibration-baseline` 标签的条件。
- 下一开发里程碑为 `v0.5.0-accel-calibration-params-baseline`。

## 19. 2026-07-30：加速度校准与参数持久化软件交付

### 目标

在 `v0.4.0-gyro-calibration-baseline` 上建立掉电安全的参数A/B槽，并实现可由
Betaflight App触发的水平单面加速度校准。

### 修改

- 程序区限制为前256 KB，Sector 6/7分别作为128 KB参数槽A/B。
- 固定48字节v1记录，包含magic、版本、长度、sequence、flags、CRC32和最后commit。
