# v1.0.0 S4.1～S4.3控制输出开发计划

## 1. 合并范围

| 阶段 | 本轮交付 | 完成边界 |
|---|---|---|
| S4.1 | 静态FlightTask，1 kHz读取一致快照并检查IMU/RC新鲜度 | 输入无效或过期时只提交停止值 |
| S4.2 | DShot300 16位编码，TIM1/TIM2 update DMA四路输出 | 软件时序与资源冻结，逻辑分析仪待验收 |
| S4.3 | 四路显式无桨测试命令、250 ms刷新超时和故障低电平 | 编号、方向、停止与断连行为待实物验收 |

本轮不实现PID、Rates、Mixer、ARM状态机、双向DShot、遥测、RPM Filter、App Motors
完整页面或参数持久化。正常飞行控制输出固定为零；唯一非零来源是显式无桨测试命令。

## 2. 板级资源

| Motor | 引脚 | Timer通道 | DMA触发与资源 |
|---|---|---|---|
| M1 | PA15 AF1 | TIM2_CH1 | TIM2_UP，DMA1 Stream1 / Channel3 |
| M2 | PA10 AF1 | TIM1_CH3 | TIM1_UP burst，DMA2 Stream5 / Channel6 |
| M3 | PA9 AF1 | TIM1_CH2 | 同上 |
| M4 | PA8 AF1 | TIM1_CH1 | 同上 |

选择update DMA而不是M1的TIM2_CH1 DMA，是因为后者只能使用已被CRSF占用的
DMA1 Stream5。当前方案不占用USART2的DMA1 Stream5、ADC3的DMA2 Stream1、SPI1的
DMA2 Stream0/3。`.ioc`继续把M1～M4保留为上电安全GPIO；`dshot_motor_init()`只在
任务启动后接管PA8～PA10、PA15为AF1。

## 3. DShot300契约

| 项目 | TIM1（M2～M4） | TIM2（M1） |
|---|---:|---:|
| Timer时钟 | 216 MHz | 108 MHz |
| ARR+1 | 720 tick | 360 tick |
| 位周期 | 3.333 us | 3.333 us |
| 0高电平 | 270 tick / 1.25 us | 135 tick / 1.25 us |
| 1高电平 | 540 tick / 2.50 us | 270 tick / 2.50 us |

帧按11位value、1位telemetry、4位异或checksum编码，MSB先发；首版telemetry固定为0。
允许值为停止值0或油门48～2047，禁止1～47保留命令。每帧后附两个低电平bit槽，DMA
再写入一个零哨兵后停止Timer，保证最后一个复位槽完整。

## 4. 接口

```c
bool dshot_motor_init(void);
uint16_t dshot_encode_frame(uint16_t value, bool telemetry);
bool dshot_motor_submit(const uint16_t values[4]);
void dshot_motor_force_safe(void);
void dshot_motor_get_diagnostics(dshot_motor_diagnostics_t *diagnostics);
void dshot_motor_dma_irq_handler(void);

void flight_task_create(void);
bool flight_task_request_motor_test(const uint16_t values[4]);
uint32_t flight_task_stack_high_water_mark(void);
```

MSP2接口：

| 命令 | 方向 | 负载 | 语义 |
|---|---|---:|---|
| `0x4005` | 读 | 64 B | FlightTask安全位、计数、四路请求/输出和栈余量 |
| `0x4006` | 写 | 8 B | 四个小端DShot值；必须持续刷新，非法值拒绝 |

## 5. 安全状态

FlightTask每1 ms通过 `app_state_get_snapshot()`取得一份一致快照，同时满足以下条件才把
测试请求提交为非零：

- IMU在线、timing/filter READY、姿态READY，且IMU样本年龄不超过5 ms。
- RC通道有效、未Failsafe，且通道帧年龄小于300 ms。
- 既有 `arming_inhibit_flags` 为0；因此校准、参数和电池关口同样必须正常。
- `0x4006`最后一次合法请求年龄小于250 ms。

任一条件失效即在下一次FlightTask周期提交四路停止值。DMA连续两个1 kHz周期仍忙或
提交失败时，驱动关闭TIM1/TIM2和两条DMA，把M1～M4切回GPIO低并锁存故障；恢复需要重启。
平台故障或Flash保存路径原有的 `platform_motor_outputs_force_safe()` 同样会把AF改回GPIO，
驱动下一次提交时检测到该状态并拒绝重新启用。

## 6. 软件与实物关口

软件完成要求：

- `Tools/verify_flight_motor.mjs`覆盖编码向量、300 kHz tick、保留命令拒绝、250 ms边界、
  DMA资源冲突、IRQ/MSP/CMake接线和测试脚本最终停止保护。
- S3全部六组回归继续通过，Debug/Release clean build通过，`git diff --check`通过。

实物完成要求见文档26：逻辑分析仪确认四路时序和checksum；拆桨逐路确认编号/方向；
脚本结束、USB断开/停止刷新、RC断链、IMU失效和DMA故障均进入停止或GPIO低电平。
