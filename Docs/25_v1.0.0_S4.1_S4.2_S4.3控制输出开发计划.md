# v1.0.0 S4.1～S4.3控制输出开发计划

## 1. 合并范围

| 阶段 | 本轮交付 | 完成边界 |
|---|---|---|
| S4.1 | 静态FlightTask，1 kHz读取一致快照并检查IMU/RC新鲜度 | 输入无效或过期时只提交停止值 |
| S4.2 | DShot600 16位编码，Betaflight F7 GPIO bitbang四路输出 | 软件时序与资源冻结，逻辑分析仪待验收 |
| S4.3 | 四路显式无桨测试命令、250 ms刷新超时和故障低电平 | 编号、方向、停止与断连行为待实物验收 |

本轮不实现PID、Rates、Mixer、ARM状态机、双向DShot、遥测、RPM Filter、App Motors
完整页面或参数持久化。正常飞行控制输出固定为零；唯一非零来源是显式无桨测试命令。

## 2. 板级资源

| 资源 | 配置 | 作用 |
|---|---|---|
| M1～M4 | PA15 / PA10 / PA9 / PA8，GPIO推挽输出 | 四路均位于GPIOA，由一次BSRR写入同步置位/复位 |
| Pacer | TIM8_CH1，216 MHz，ARR=119 | 每0.556 us产生一次CC1 DMA请求；不把TIM8输出映射到电机引脚 |
| DMA | DMA2 Stream2 / Channel7，memory-to-peripheral word | 把51个32位状态字依次写入`GPIOA->BSRR` |

该选择来自原始`E:\betaflight`的实际默认链路，而不是重新设计：GETFUNF722V3未覆盖
`DEFAULT_DSHOT_BITBANG`，STM32F7的`AUTO`会启用bitbang；其第一组pacer资源正是
`TIM8_CH1 -> DMA2 Stream2 / Channel7`。四路电机都在GPIOA，因此只需一组pacer和一条
DMA。当前方案不占用USART2的DMA1 Stream5、ADC3的DMA2 Stream1、SPI1的DMA2
Stream0/3。`.ioc`继续把M1～M4保留为上电安全GPIO，运行期间也不再切换为TIM1/TIM2 AF。

## 3. DShot600契约

| 项目 | Betaflight F7 bitbang值 |
|---|---:|
| Pacer Timer时钟 | 216 MHz |
| 每状态ARR+1 | 120 tick |
| 每bit状态数 | 3 |
| 位周期 | 360 tick / 1.667 us |
| 0高电平 | 120 tick / 0.556 us |
| 1高电平 | 240 tick / 1.111 us |

帧按11位value、1位telemetry、4位异或checksum编码，MSB先发；首版telemetry固定为0。
允许值为停止值0或油门48～2047，禁止1～47保留命令。每bit的三个DMA状态依次为
“四路置高、按0/1选择性拉低、四路全部拉低”；16 bit后再发三个保持低电平的状态，
共51个word。TIM8持续作pacer，帧结束中断关闭CC1 DMA请求并让GPIO保持低电平。

MSP2接口：

| 命令 | 方向 | 负载 | 语义 |
|---|---|---:|---|
| `0x4005` | 读 | 64 B | FlightTask安全位、计数、四路请求/输出和栈余量 |
| `0x4006` | 写 | 8 B | 四个小端DShot值；必须持续刷新，非法值拒绝 |

## 5. 安全状态

FlightTask每1 ms通过 `app_state_get_snapshot()`取得一份一致快照，同时满足以下条件才把
测试请求提交为非零：

- IMU在线、timing/filter READY、姿态READY，且IMU样本年龄不超过5 ms。
- RC通道有效、未Failsafe，且通道帧年龄小于300 ms。
- 既有 `arming_inhibit_flags` 为0；因此校准、参数和电池关口同样必须正常。
- `0x4006`最后一次合法请求年龄小于250 ms。

任一条件失效即在下一次FlightTask周期提交四路停止值。DMA连续两个1 kHz周期仍忙或
提交失败时，驱动关闭TIM8_CH1 DMA请求和DMA2 Stream2，把M1～M4保持为GPIO低并锁存故障；
恢复需要重启。平台故障路径原有的`platform_motor_outputs_force_safe()`同样会保持电机GPIO低。
