# S7.8 拆桨端到端联合验收

> 当前状态：✅ 开发者于 2026-08-22 确认事件式手势、基础油门透传和拆桨端到端验收通过。

## 1. 这次要证明什么

从摄像头看到手，到飞控生成最终电机输出，中间每一步都能看到、能对上、出错会立即回到物理遥控器。
链路如下：

```text
摄像头 -> 手势 -> Linux候选RC -> 飞控RC -> 控制目标 -> PID/Mixer -> DShot电机值
```

始终拆除螺旋桨。Linux 不能解锁飞控，不能改变 AUX，不能绕过 Failsafe；物理遥控器仍可随时撤销和接管。

## 2. 开始前的准备

1. 拆掉螺旋桨；电机动力可以断开时优先断开。
2. 保存 RK3568 的标准输出到 `linux.jsonl`，保存飞控 UART4 输出到 `flight.log`。
3. 物理遥控器设置：AUX1=ARM、AUX2=ANGLE、AUX3=视觉授权；上电前三者均为低位，油门最低。
4. 启动 Linux 实时程序时，`S7_6_RC_OUTPUT` 只能设置为已确认接到飞控 USART6 的串口设备。不能接 UART2/CRSF。
5. 保持无手，先确认 Linux 日志为 `virtual_rc_valid:true`、`virtual_rc_gesture_name:"UNKNOWN"`、五通道全 0；再 ARM 并完成 AUX3 低到高授权，授权前不要先做动作手势。

## 3. 两端日志怎么对

Linux 一条 JSON 记录中：

| 字段 | 意义 |
|---|---|
| `sequence` | 摄像头帧号 |
| `active_gesture_name` | 最终生效的手势；不是观察到但尚未确认的手势 |
| `virtual_rc_valid` | 此帧是否已送出有效候选 RC |
| `virtual_rc_gesture_name` | 线上命令手势；转换帧沿用上一个命令 ID，目标期结束后回中 |
| `virtual_rc_source_sequence` | 送给飞控的源序号，必须等于本条 `sequence` |
| `virtual_rc_channels` | Linux 发出的 Roll、Pitch、Yaw、Throttle、AUX；后两项始终应为 0 |

飞控每秒有一条 `e2e` 日志：

```text
e2e rc_source=1 rc_valid=1 rc_seq=318 rc_hb=901 setpoint_valid=1 setpoint_mode=0 pid_valid=1 mixer_valid=1 flight_ready=1 armed=1 failsafe=0 dshot_ready=1 dshot_busy=0 motors=[...]
```

判断方式：Linux 的 `virtual_rc_source_sequence=318` 应在飞控日志中出现 `rc_seq=318` 或随后更大的值。
`rc_source=1` 表示飞控已经接管 Linux 候选；随后 `setpoint_valid/pid_valid/mixer_valid/flight_ready`
都应为 1。发生撤销或故障时，`rc_source` 必须回到 0，且不能保留旧动作。

## 4. 最小通过流程

### A. 授权后中立

1. 保持无手，确认 Linux 持续发送有效 UNKNOWN 中立帧。
2. 物理油门最低时 ARM；拆桨条件下再给定一个低测试油门，记录 Receiver Throttle 和四电机基础值。
3. 将 AUX3 从低位拨到高位，确认飞控 `rc_source=1`，随后 `setpoint_valid=1`、`pid_valid=1`、`mixer_valid=1`。
4. 继续保持无手至少 3 秒，确认 `rc_source=1` 稳定且电机保持基础值；此时不要出现姿态差动。

通过标准：控制链有效，RPY 保持中立；有效 Throttle 和四电机基础值保持物理遥控器给定值，Linux 不改变 Throttle 或 AUX。

### B. 三个单次动作

1. 依次让张掌、单指和 V 字重新进入 `ACTIVE`，每个手势均保持到命令自动回中。
2. 每次转换期间确认 `virtual_rc_valid:true`、当前命令不会在 1 s 前被截断、命令结束后通道回中且飞控 `rc_source=1`。
3. 对照 Linux 的 `virtual_rc_channels` 和飞控 `rc_seq`、`setpoint`、`control pid`、`mixer` 日志。

通过标准：张掌只产生一次 Pitch 负向（低头前向）脉冲，单指只产生一次 Pitch 正向（抬头后向）脉冲，V 字只产生
一次 Roll 负向脉冲；每次目标命令完整保持 1 s 后开始自动回中，保持手势不重复触发。Yaw/AUX 不变，
Throttle 持续跟随物理遥控器，姿态差动叠加在其基础油门上；正常转换不退出 Linux。

### C. 立即退出

在虚拟源活动时分别执行：AUX3 拉低、移动物理 Roll/Pitch/Yaw、握拳、制造摄像头/推理故障、
杀死 Linux 进程、拔开 Linux TX、重启 Linux 程序。

通过标准：每一项都让 `rc_source` 回到 0；Receiver 和控制链立即改回物理遥控器，不保留旧虚拟 Roll/Pitch/Yaw，Throttle 全程保持物理值。
Linux 恢复后必须重新完成 AUX3 低到高授权，不能自动重入。

另做一项非退出测试：保持 `rc_source=1`，在拆桨安全范围内改变物理 Throttle。预期 `rc_source`
不变、有效 Throttle 立即跟随、四电机基础值整体变化；随后触发手势，姿态差动应叠加在新的基础值上。
再移开手或在手势间正常转换，预期持续发送有效 UNKNOWN 中立、`rc_source=1` 不变，不需要重新拨 AUX3。

## 5. 记录与自动检查

Linux JSONL 可先执行以下离线检查：

```powershell
node Tools/verify_s7_8_trace.mjs C:\path\to\linux.jsonl
```

它会检查摄像头帧序号、虚拟 RC 心跳、源序号对齐、有效帧的 Throttle/AUX 为 0，以及无效帧是否全通道释放。
再将 Linux 和飞控日志一起检查：

```powershell
node Tools/verify_s7_8_e2e.mjs C:\path\to\linux.jsonl C:\path\to\flight.log
```

第二个脚本只看 `e2e` 行。它会明确检查：飞控有没有真正选中 Linux（`rc_source=1`）、飞控采用的
`rc_seq` 能否在 Linux 日志中找到对应或更早的有效手势帧，以及被选中期间 RC、setpoint、PID、Mixer、
飞控就绪和 DShot 就绪是否完整，Failsafe 是否保持关闭。输出 `PASS` 才表示这份日志没有发现断链；
输出 `FAIL` 会直接指出文件和字段。两个脚本都不能替代真实硬件验收。

## 6. 本阶段禁止事项

- 不装螺旋桨，不离地，不进行飞行测试。
- 不改动 ARM/Failsafe 门禁来“方便验收”。
- 不把 `source=1` 当作一切正常；必须同时检查控制链和故障退出。
- 不因 Linux 数据恢复而跳过 AUX3 低到高重新授权。

## 7. 完成标准

所有冻结手势、无手/遮挡、摄像头或NPU故障、串口断线、Linux/飞控重启、AUX3撤销和物理接管都完成
拆桨记录；两端日志能够以源序号对齐；连续运行30分钟没有旧动作残留、自动 ARM、复位或无法解释的错误增长。
开发者于 2026-08-22 确认以上项目全部通过，S7.8 据此关闭并纳入
`v1.6.0-s7.8-gesture-rc-baseline`。该结论不自动允许装桨或飞行；S7.9 仍按独立安全前置条件执行。
