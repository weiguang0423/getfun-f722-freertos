# S7.6 手势到虚拟 RC 映射与发送链路开发验收

> 当前状态：✅ 开发者于 2026-08-20 明确确认验收成功；后续阶段不得重复要求 S7.6 检验

## 1. 已确认的入口与安全边界

开发者已明确确认 S7.5 验收通过，本阶段不重复检查 S7.5 实物数据。S7.6 只消费 S7.5 的
`GestureSnapshot`，生成 Linux 候选帧。STM32 USART6 已增加只读帧监视，用于通过 UART4 确认收字节、
帧边界、CRC 和字段；源仲裁仍留在 S7.7，因此本阶段不能把候选值直接
写入 setpoint、PID、Mixer 或 DShot，也不能生成 ARM 和总授权通道。

硬件文档 01 已确认飞控 UART2 被 CR8 ELRS/CRSF 使用；本次已将飞控 Linux 通信/诊断物理口切换为
USART6（PC6=TX、PC7=RX）。RK3568 侧实际 UART 设备、电平和接线仍需实物核对，程序通过
`S7_6_RC_OUTPUT` 显式选择设备，禁止默认复用或并接 UART2。串口参数冻结为 115200 8N1。

## 2. 映射与失效契约

首版只开放低幅度姿态候选，完整表见 `Linux/RK3568/s7_6/README.md`：张掌为有效中立，握拳为
显式释放，单指为 Pitch -0.30，V 字为 Yaw +0.30。Roll、Throttle 和 AUX 当前保持释放值；这不是
未来扩动作的占位抽象，而是进入 S7.7 前的主动安全限制。

通道整数尺度、范围和变化率：

| 通道 | 中立/释放 | 合法范围 | 最大变化率 | 首版实际目标 |
|---|---:|---:|---:|---:|
| Roll | 0 | -300～+300 | 600/s | 0 |
| Pitch | 0 | -300～+300 | 600/s | 0 或 -300 |
| Yaw | 0 | -300～+300 | 600/s | 0 或 +300 |
| Throttle | 0 | 0～250 | 400/s | 0 |
| AUX | 0 | 0～1000 | 1000/s | 0 |

有效动作按变化率接近目标，任何无效条件则不等待斜坡并立即全通道释放。`valid=1` 同时要求：

- S7.5 状态为 `ACTIVE`，观测 ID 等于活动 ID，置信度不低于 0.75；
- 不是 `UNKNOWN` 或显式释放手势 `FIST`；
- 源和发送时间均为单调时钟，时间未回退，源年龄不超过 250 ms。

启动第一帧固定无效；串口写失败抛错终止进程，不自动重连。进程重启后 S7.5 也从无历史状态
重新确认，因此旧动作不会自动恢复。

## 3. 帧与接收拒绝规则

固定帧共 44 字节，包含魔数/版本/帧长、有效位、手势 ID、置信度、源序号、发送心跳、源/发送
时间戳、五个 `int16` 通道和 CRC16-CCITT-FALSE。实时链沿用 S7.4/S7.5 已冻结的 20 fps，因此
正常发送周期为 50 ms。源序号允许因最新帧策略跳号但必须前进，心跳每次发送加一。

`decode()` 已实现下一阶段接收边界的纯逻辑参考。以下任一情况必须拒绝：

- 魔数、版本、帧长、保留位或 CRC 错误；
- 任一通道超出冻结范围；
- 心跳未前进，或有效帧源序号未前进；
- 接收时距发送超过 150 ms；
- 有效帧的源结果年龄超过 250 ms；
- 无效帧仍携带非零通道，或有效帧携带未知/释放手势。

## 4. 当前软件结果

- x86 WSL 使用 C++17、`-Wall -Wextra -pedantic` 编译并运行纯逻辑自检，输出
  `s7.6 virtual RC self-test ok`。
- 同一环境通过临时文件运行真实 `SerialLink::send` 写出与两帧解码回环，输出
  `s7.6 serial loopback self-test ok`；这证明软件写出路径，不代替 UART 电气验收。
- 自检覆盖启动无效、Pitch 限速和最终限幅、Throttle/AUX 保持释放、编解码往返、CRC 损坏、
  150 ms 过期、旧源序号和握拳立即释放。
- 使用现有 RK3568 SDK 成功生成 ARM64 ELF，大小 112992 字节，SHA-256 为
  `61cfff8d59ed8ce28f42836fdfc875cef54ae01f3ca01bcda38135adac9933fb`。
- x86 WSL 执行 ARM64 产物会得到 `Exec format error`，这是主机架构边界，不是板端自检结果。

## 5. 已关闭的实物关口（保留原过程供追溯）

1. 在 RK3568 执行 `s7_6_live --self-test`，返回码为 0。
2. 核对 RK3568 UART 引脚、电平和飞控空闲 UART；不得与 UART2/CRSF 两发送端并接。
3. 用串口回环或逻辑分析仪验证 115200 8N1、44 字节、20 Hz、CRC、源序号和心跳。
4. 四种手势、无手、未知、低置信度、遮挡和快速切换逐项核对 `virtual_rc_*` JSON 与线上帧。
5. 验证轴限幅和 600/s 变化率；Throttle/AUX 始终为 0，握拳和任一故障当前帧立即全释放。
6. 拔线、杀死进程和重启：接收观察端在 150 ms 内判为链路失效，恢复后不得自动恢复动作。

开发者于 2026-08-20 明确确认以上 S7.6 验收成功，并要求直接进入 S7.7，后续不再重复检查
S7.6。该确认只关闭映射与发送链路阶段，不把 S7.7 的人工授权、源仲裁或飞控安全链验收倒推为
已经完成；这些新增行为按文档 42 单独验收。
