# S7.7 飞控 RC 源仲裁、人工授权与 Failsafe 开发验收

> 当前状态：✅ 2026-08-22 事件式映射、物理 Throttle 透传、AUX3 授权和故障退出已确认通过
>
> 前置确认：开发者于 2026-08-20 明确确认 S7.6 验收成功，并要求不再重复检验；本文只验 S7.7 新增行为

## 1. 本阶段验收目标

S7.7 只在飞控 RC 输入边界选择“物理 RC”或“Linux 虚拟 RC 候选”。仲裁结果写入原有
`app_state.rc.mapped_channel_us`，后续仍走既有 `rc_setpoint -> Angle/Rate PID -> Mixer ->
ARM/Failsafe -> DShot`，没有在 setpoint、PID、Mixer 或电机提交处增加旁路。

本阶段必须证明：

1. 上电、物理 RC 无效、未 ARM、AUX3 未完成低高授权、AUX3与ARM/ANGLE配置冲突或 Linux 候选无效时，只能使用物理 RC。
2. AUX1 继续独占 ARM，AUX2 继续独占 ANGLE，AUX3 作为 S7.7 专用总授权；Linux 的 AUX 字段不进入飞控 AUX。
3. 只有物理 RC 已 ARM、无任何 `arming_inhibit`、物理摇杆处于接管安全区、AUX3 先低后高且 Linux 候选新鲜时，虚拟源才可进入。
4. 撤销 AUX3、移动物理 Roll/Pitch/Yaw、Linux 无效/超时/重启、串口非法帧、飞控 inhibit、物理 RC 失效或 DISARM，均立即退出虚拟源。
5. 任一退出后，即使 Linux 恢复，也必须先把 AUX3 拉低并保持至少一个 RcTask 周期，再重新拉高；不得自动恢复旧动作或自动 ARM。
6. 进入虚拟源时仅 Roll/Pitch/Yaw 按冻结变化率接近 Linux 目标；Throttle 始终采用物理遥控器实时值，不参与 Linux 合成，也不触发退出。

## 2. 冻结接口和参数

### 2.1 通道所有权

| 通道 | 虚拟源激活前 | 虚拟源激活后 | 退出时 |
|---|---|---|---|
| Roll/Pitch/Yaw | 物理 RC | Linux 候选经二次限速后合成 | 立即回到物理 RC |
| Throttle | 物理 RC | 始终为物理 RC；可在基础油门上叠加姿态手势 | 始终为物理 RC |
| AUX1 / 内部索引 4 | 物理 RC ARM | 始终为物理 RC | 始终为物理 RC |
| AUX2 / 内部索引 5 | 物理 RC ANGLE | 始终为物理 RC | 始终为物理 RC |
| AUX3 / 内部索引 6 | 物理 RC 总授权 | 始终为物理 RC | 拉低即撤销并锁住重入 |
| 其他 AUX | 物理 RC | 始终为物理 RC | 始终为物理 RC |

### 2.2 仲裁门槛

| 项目 | 冻结值 | 边界语义 |
|---|---:|---|
| AUX3 授权有效 | `>= 1700 us` | 上电高位不能授权，必须先观察到低位再上升 |
| AUX3 配置独占 | ARM/ANGLE 均不得使用内部通道 6 | 冲突时禁止进入，活动中发现冲突立即退出 |
| Roll/Pitch/Yaw 人工接管 | 距 `1500 us` 大于 `150 us` | 任一轴越界立即退出虚拟源 |
| Linux 接收超时 | `150 ms` | 候选年龄达到 150 ms 即失效，使用无符号差支持 Tick 回绕 |
| Roll/Pitch/Yaw 二次变化率 | `600 us/s` | 即使授权前 Linux 已到目标，进入时也不跳到目标 |
| 单次限速最大时间步 | `100 ms` | 任务阻塞后不允许一次追完大跨度目标 |

### 2.3 USART6 候选拒绝规则

接收器在 ISR 中完成固定 44 字节同步和校验，只向 RcTask 暴露原子候选快照。以下任一条件会在
当前完整帧立即把候选标为无效：CRC 错误、版本/长度/保留位错误、手势或通道越界、无效帧仍有
非零通道、动作帧置信度低于 75%、有效帧为 FIST、UNKNOWN 帧不是置信度 0/全通道 0、手势与允许轴不一致、当前版本
Throttle/AUX 非零、源时间晚于发送时间、源年龄大于 250 ms、心跳未前进、有效
源序号未前进或 UART 错误。没有形成完整帧的拔线/停发由 150 ms 本地接收超时关闭。

发送进程在超过 150 ms 的断流后允许心跳从低值重新开始，但接收器递增会话代数。若虚拟源正在
工作，会话代数变化立即触发 `VIRTUAL_RESTART` 退出；恢复流量仍不能绕过 AUX3 低高重新授权。

## 3. 实现位置和数据流

```text
USART2 CRSF/DMA -> RcTask -> physical_mapped_channel_us --------------------+
                                                                            |
USART6 IRQ -> linux_rc_monitor -> validated rc_virtual_candidate_t --------+-->
                                                                            rc_source_arbiter
app_state.flight.armed + arming_inhibit_flags ------------------------------+-->
                                                                            mapped_channel_us
                                                                                  |
                                                                                  v
rc_setpoint -> Angle/Rate PID -> Mixer -> flight_arming/Failsafe -> DShot
```

- `linux_rc_monitor` 只负责帧校验、进度、会话和候选快照，不直接发布 RC。
- `rc_source_arbiter` 是不依赖 HAL/FreeRTOS 的纯 C 安全状态机，便于在主机执行实际代码。
- `RcTask` 仍是 RC 单写者，同时保留物理映射和发布最终有效映射。
- `FlightTask`、`rc_setpoint`、PID、Mixer、ARM/Failsafe 和 DShot 无虚拟 RC 专用入口。
- UART4 每秒输出接收错误计数、候选年龄、活动源、授权/重新授权状态、进入/退出次数和退出原因。

### 3.1 验收人员只需要先看什么

每秒会出现一行类似下面的日志：

```text
rc source=1(virtual) auth=1 reauth=1 virtual=1 age_ms=42 seq=318 hb=901 gen=0 enter=1 exit=0 reason=0(none) transition_age_ms=6000 aux3_us=1880 armed=1 inhibit=0x00000000 cfg=1
```

不要先背字段。按下面顺序判断即可：

1. 看 `source`：`0(physical)` 表示现在由遥控器控制，`1(virtual)` 表示现在由 Linux 手势控制。
2. 想让它变成 `1`，必须同时满足：`auth=1`、`armed=1`、`inhibit=0`、`cfg=1`、`virtual=1`，并且先看到过 `reauth=1`。
3. `source` 还是 `0` 时，逐个看上面五个条件，哪个不满足就是原因，不要只盯着 `source`。
4. `age_ms` 是最近一帧 Linux 数据距现在的毫秒数。小于 150 才算新鲜；没有数据时不用于判断授权。
5. `reason` 只在从虚拟控制退回物理控制后说明“为什么退回”。括号里的中文/英文名称比数字更重要。

### 3.2 字段对照表

| 日志字段 | 人话解释 | 验收时怎么用 |
|---|---|---|
| `source` | 当前谁在控制 | `0(physical)` 物理遥控器；`1(virtual)` Linux |
| `auth` | AUX3 是否拨到授权位置 | `1` 才允许尝试切换；AUX3 必须来自物理遥控器 |
| `reauth` | 退出后是否重新解锁 | 退出后先把 AUX3 拉低，看到 `1` 后才能再次拉高进入 |
| `virtual` | Linux 最近数据是否有效且新鲜 | `1` 才有资格进入，不代表已经进入 |
| `age_ms` | 最近 Linux 数据有多旧 | 小于 `150` 才正常，单位是毫秒 |
| `seq`、`hb`、`gen` | 数据连续性检查值 | 正常运行时 `seq/hb` 持续增加；重启发送程序时 `gen` 增加 |
| `enter`、`exit` | 进入/退出次数 | 每次切换应各增加一次 |
| `reason` | 最近一次退出原因 | `1` AUX3 撤销；`2` 物理摇杆接管；`3` Linux 数据无效；`4` 超时；`5` 发送端重启；`6` 飞控禁止解锁；`7` 已解除 ARM；`8` 物理遥控器失效；`9` AUX3 配置冲突 |
| `aux3_us` | AUX3 实际脉宽 | 低位通常约 1000，高位通常约 2000；拨杆时这个值必须变化 |
| `armed` | 飞控是否已 ARM | 必须为 `1` |
| `inhibit` | 飞控当前是否有禁止解锁的故障 | 必须为 `0x00000000` |
| `cfg` | AUX3 是否被错误配置给 ARM/ANGLE | 必须为 `1` |

### 3.3 三个最常见的验收结果

| 看到的日志 | 结论 | 下一步 |
|---|---|---|
| `source=0`、`aux3_us` 随拨杆变化、`virtual=0` | Linux 没有提供有效数据 | 查 `linux_rc` 行、串口和发送程序 |
| `source=0`、`virtual=1`、但 `armed=0` 或 `inhibit` 非零 | Linux 正常，但飞控安全条件未满足 | 先按物理遥控器完成 ARM 和安全检查 |
| `source=0`、`virtual=1`、`armed=1`、`inhibit=0`，但 `reauth=0` | 重新授权锁未解除 | AUX3 拉低，等一秒，再拉高 |

实现来源选择为“完全自主实现”。原因是源仲裁和重新授权属于项目特有的安全所有权规则，直接引入
通用飞控或遥控库会同时带入不匹配的任务、ARM 和通道语义。本阶段继续复用仓库内 ST HAL、
FreeRTOS 和既有 CRSF 基础设施，没有新增第三方组件、动态内存或构建时联网依赖。

### 5.4 启动日志故障定位与栈修复验收

此前实机日志只到 `RTOS: starting`。源码执行路径显示：该行在 `osKernelStart()` 前输出；调度器启动后，`InitTask` 才会依次执行 `MX_USB_DEVICE_Init()`、输出 `RTOS: started` 和 1 Hz 心跳。因此缺少 `RTOS: started` 不是正常的日志精简，而是系统在 InitTask 运行前已经停滞或故障。

与实机日志构建时间对应的原 S7.7 Debug ELF 通过 `.su` 栈用量确认：`RcTask` 固定栈帧为 1800 B，而任务配置为 512 words，即 2048 B；新增的完整 `app_state_snapshot_t` 为 1144 B，导致高优先级 RcTask 首轮运行时只剩约 248 B，存在栈溢出并阻止最低优先级 InitTask 输出后续日志的确定性风险。

修复内容如下：

1. 在 `app_state` 增加 `app_state_get_rc_source_context()`，在临界区内只读取 `armed`、`arming_inhibit_flags` 和 AUX3 配置冲突状态。
2. `RcTask` 用不超过 16 B 的 `app_rc_source_context_t` 替代完整系统快照，不改变仲裁规则、通道所有权、Failsafe 或 S7.6 USART6 接收协议。
3. 增加编译期栈预算断言，防止任务栈配置被误降到未经验证的范围。

修复后的 `.su` 结果：

| 配置 | RcTask 静态栈帧 | 任务总栈 | 余量（仅按静态帧估算） | 结论 |
|---|---:|---:|---:|---|
| Debug | 664 B | 2048 B | 1384 B | 通过 |
| Release | 728 B | 2048 B | 1320 B | 通过 |

## 6. 实物验收前置条件

开始以下步骤前必须全部满足：

- 拆除四个螺旋桨，并拍照或记录“已拆桨”；电机可以断电时优先断开电机动力。
- 飞控固定在绝缘台面，USB、调试器、UART4 观察口和急停电源均可立即断开。
- 物理 RC/ELRS 已绑定，AUX1=ARM、AUX2=ANGLE、AUX3=视觉总授权，三者开关位置可明确辨认。
- RK3568 到飞控只接已验收的 USART6 链路，共地和电平按 S7.6 已验收结论，不复用 UART2/CRSF。
- 烧录本文第 5.3 节对应的同一 Debug 或 Release BIN，并记录实际使用配置和 SHA-256。
- UART4 以 115200 8N1 持续保存完整日志；Betaflight App/Configurator 打开 Receiver 和 Motors 页面但不得发送 Motor Test。
- 上电前 AUX1、AUX2、AUX3 均低，Throttle 最低，Roll/Pitch/Yaw 回中。

任一前置条件不满足，停止验收，不用“手扶电机”“短时间装桨”代替安全条件。

## 7. 实物验收详细过程

### 7.1 上电与纯物理 RC 基线

1. 不启动 RK3568，或断开它到飞控的串口。确认拆桨后再上电。
2. 等待 UART4 出现 `RTOS: started` 和周期性 `heartbeat`。
3. 保持 AUX1、AUX2、AUX3 都在低位，在日志中找到 `rc source` 行。
4. 确认 `source=0(physical)`、`virtual=0`、`enter=0`。
5. 拨动 AUX3 高低，确认只有 `auth` 和 `aux3_us` 变化，`source` 仍为 `0(physical)`。

通过标准：遥控器通道正常显示，AUX3 高位不能单独启动 Linux 控制；电机保持安全状态。
如果上电后出现 `source=1(virtual)`，立即断电，记录完整日志并判定失败。

### 7.2 Linux 帧接收与候选诊断

1. AUX1、AUX3 保持低位，启动已经通过 S7.6 验收的 RK3568 发送程序。
2. 保持无手，确认 `virtual=1`、`age_ms<150`、候选通道全 0，并且 `seq`、`hb` 持续增加。
3. 做“张掌”，确认候选 Pitch 产生一次负向脉冲并回中；再移开手，确认 `virtual=1` 且保持中立。
4. 做“握拳”，确认 `virtual=0`。恢复无手后候选重新有效，但因为尚未 ARM/AUX3 授权，`source` 仍为 `0(physical)`。

通过标准：Linux 数据可以正常变为有效/无效，但在没有 ARM 和 AUX3 授权时，绝不能接管飞控。

### 7.3 ARM 所有权和首次授权

1. 保持油门最低、Roll/Pitch/Yaw 回中、AUX3 低位，Linux 持续发送有效中立帧。
2. 只把 AUX1 拉高，确认日志中 `armed=1`；此时 `source` 应仍为 `0(physical)`。
3. 拆桨条件下把物理油门调到选定的低测试值，记录 Receiver Throttle 和四电机基础值；再把 AUX3 拉高。
4. 若仍是 `source=0`，按 3.1 的顺序检查 `virtual`、`age_ms`、`armed`、`inhibit`、`cfg`、`reauth`。
5. 若变为 `source=1(virtual)`，记录 `enter` 增加 1，并确认 Receiver 中 Throttle、AUX1/AUX2/AUX3 仍跟随物理遥控器，基础油门和四电机基础值不应因接管而归零。

通过标准：AUX1 负责 ARM，AUX3 只负责授权；Linux 不能改变 ARM、ANGLE 或任何 AUX 通道。
进入虚拟控制时 RPY 保持中立、物理基础油门不变；授权完成后新出现的手势才开始一次动作。

### 7.4 冻结手势到有效 RC 快照

在保持拆桨、ARM 和 AUX3 授权的前提下逐项执行。每个手势首次 `ACTIVE` 只触发一次，
持续保持同一手势时必须自动回中且不重复触发：

| 手势 | Receiver/UART4 预期 | 禁止现象 |
|---|---|---|
| 张掌 | Pitch 向 1200 us 限速变化，目标保持 1 s 后自动回到 1500 us | 保持手势导致连续前向命令 |
| 单指 | Pitch 向 1800 us 限速变化，目标保持 1 s 后自动回到 1500 us | Roll/Yaw 跟随变化或物理 Throttle 被覆盖 |
| V 字 | Roll 向 1200 us 限速变化，目标保持 1 s 后自动回到 1500 us | Pitch/Yaw 跟随变化或 Throttle/AUX 被覆盖 |
| 健康无手/正常切换 | 持续保持 `source=1`，当前命令执行满目标期后 RPY 回中，新手势 ACTIVE 后触发一次 | 命令被转换帧提前截断，或 `source=0` 要求重新拨 AUX3 |
| 握拳 | 当前帧退出到物理 RC，`reason=3`（VIRTUAL_INVALID） | 继续保持虚拟动作 |

握拳退出后保持 AUX3 高，再次张掌至少 2 秒：必须仍为 `source=0`。随后 AUX3 拉低，确认
`reauth=1`，再拉高才允许 `source=1` 和 `enter` 再加 1。

### 7.5 人工撤销和物理摇杆接管

退出类子项都从“已 ARM、AUX3 已低高授权、`source=1`、V 字或单指动作稳定”开始；退出后必须
重新执行 AUX3 低高授权，不能沿用上一项状态。第 5 项专门验证活动期间的物理油门所有权，不应退出。

1. AUX3 撤销：拉低 AUX3。预期 `source=0`、`reason=1`，当前帧恢复物理 RC。
2. Roll 接管：物理 Roll 从中心向任一方向移动超过 150 us。预期 `reason=2`。
3. Pitch 接管：物理 Pitch 偏离中心超过 150 us。预期 `reason=2`。
4. Yaw 接管：物理 Yaw 偏离中心超过 150 us。预期 `reason=2`。
5. Throttle 所有权：保持 `source=1`，在拆桨安全范围内改变物理 Throttle。预期 `source` 仍为 1，Receiver 有效 Throttle 实时跟随物理值，四电机基础值同步整体变化，手势只在其上产生姿态差动。
6. DISARM：物理 AUX1 拉低。预期立即退出，飞行状态 DISARM，电机安全，Linux 不得重新 ARM。

边界补充：恰好 150 us 的轴偏差不触发接管；超过门槛的第一个 RcTask 周期必须触发。Throttle
在任意有效物理范围内均不触发接管。退出后的有效通道必须等于当时物理 RC，不得停留在旧虚拟姿态值。

### 7.6 断流、拔线和进程重启

1. 激活单指或 V 字，确认 `source=1` 和虚拟动作已稳定。
2. 记录最后一个有效帧到达时间，然后杀死 RK3568 发送进程。
3. 用 UART4 高频原始日志或逻辑分析仪测量停止接收至 `source=0` 的时间。
4. 保持 AUX3 高并重启发送进程，等待有效帧恢复 3 秒。
5. 确认仍为物理源，再执行 AUX3 低高授权恢复。
6. 依次用“拔开 Linux TX”“RK3568 重启”重复步骤 1～5。

预期结果：停发/拔线在候选年龄达到 150 ms 时退出，允许一个 RcTask 调度周期的观察误差；进程或
RK3568 重启即使流量恢复也不能自动重入。接收器会话重置时 `restart`/`gen` 增加，若当时仍活动则
退出原因为 `5`（VIRTUAL_RESTART）。任何情况下都不得保持旧虚拟 Roll/Pitch/Yaw；Throttle 始终保持物理所有权。

### 7.7 非法帧与飞控安全故障注入

在 USART6 上使用已验证的串口帧注入器或逻辑分析仪串口发生功能，每次先发连续合法有效帧并完成
AUX3 低高授权，然后只改变一个条件：

| 注入项 | 观察计数 | 预期仲裁结果 |
|---|---|---|
| CRC 翻转 | `crc` 加 1 | 候选当前帧无效，`source=0` |
| 版本/长度/保留位错误 | `fmt` 加 1 | 候选当前帧无效，`source=0` |
| Roll/Pitch/Yaw 或 Throttle 越界 | `fmt` 加 1 | 候选当前帧无效，`source=0` |
| 重复/倒退心跳 | `seqerr` 加 1 | 候选当前帧无效，`source=0` |
| 有效源序号重复/倒退 | `seqerr` 加 1 | 候选当前帧无效，`source=0` |
| 源时间晚于发送时间或年龄大于 250 ms | `timeerr` 加 1 | 候选当前帧无效，`source=0` |
| 无效帧携带非零通道 | `fmt` 加 1 | 候选当前帧无效，`source=0` |
| 有效帧置信度低于75%或手势/轴不匹配 | `fmt` 加 1 | 候选当前帧无效，`source=0` |
| 当前版本有效帧的Throttle/AUX非零 | `fmt` 加 1 | 候选当前帧无效，`source=0` |

每项故障后继续发送合法帧但保持 AUX3 高，确认不能自动重入；完成 AUX3 低高后才可重入。

在 Configurator Modes 页面分别尝试把 ARM 或 ANGLE 配置到 AUX3 并保存，随后重复授权流程；预期
保持 `source=0`，活动中出现冲突时退出原因是 `9`（CONFIGURATION_INVALID）。恢复 ARM=AUX1、
ANGLE=AUX2并保存后，仍须 AUX3 低高动作才能重新进入。

飞控 inhibit 注入只使用现有安全方法，例如断开已确认可安全断开的传感器/电池检测条件或触发物理
RC Failsafe，不得短接电源或带电改接不明引脚。任一 `arming_inhibit_flags != 0` 时，预期退出原因为
`6`（FLIGHT_INHIBIT）；物理 RC 失效预期原因为 `8`，并继续由既有 ARM/Failsafe 停机链处理。

### 7.8 长时稳定和日志一致性

1. 拆桨条件下连续运行 30 分钟，前 10 分钟物理源，中间 10 分钟虚拟中立/动作切换，后 10 分钟
   重复授权、撤销和接管。
2. 每分钟保存 UART4 的 `linux_rc`、`rc source`、`rc failsafe`、`flight` 和任务栈水位。
3. 结束时记录接收帧数、CRC/格式/序号/时间错误、进入/退出次数、RcTask 最小栈水位、堆最低水位、
   飞控复位次数和 RK3568 进程异常次数。

预期结果：无复位、无栈溢出、无持续旧动作；无主动注入时错误计数不增长；每次 `enter` 都能由一次
AUX3 低高授权解释，每次 `exit` 都能由日志中的唯一原因解释。

## 9. 通过和失败判据

全部 P1～P15 已由开发者于 2026-08-22 确认符合预期，S7.7 状态据此为 ✅。以下任一项仍属于回归失败：

- 上电 AUX3 高位、未 ARM或存在 inhibit 时进入虚拟源；
- Linux 改变 AUX1/2/3、生成 ARM、绕过 PREARM/Failsafe 或直接影响电机接口；
- 撤销、接管、非法帧、停发或重启后仍保持旧虚拟动作；
- 流量恢复但未完成 AUX3 低高动作就自动重入；
- 150 ms 超时明显超限且不能由记录到的任务阻塞解释；
- 进入时 RPY 瞬跳超出冻结变化率，或虚拟源活动/退出后 Throttle 不等于物理 RC；
- 30 分钟内发生复位、栈溢出、无法解释的错误增长或源切换。

S7.7 与后续 S7.8 均已通过并纳入 `v1.6.0-s7.8-gesture-rc-baseline`。该结论仍不单独授权
安装螺旋桨或进入受控飞行；S7.9 必须满足其独立安全前置条件。
