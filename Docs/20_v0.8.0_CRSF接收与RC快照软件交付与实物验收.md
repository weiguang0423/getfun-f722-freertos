# v0.8.0 CRSF接收与RC快照软件交付与实物验收

> 目标标签：`v0.8.0-crsf-rc-baseline`  
> 当前结论：软件完成，真实硬件未验收，不得创建标签

## 1. 软件交付摘要

本次已经实现：

- USART2 PA2/PA3，420000 baud 8N1。
- DMA1 Stream 5 / Channel 4循环RX和UART IDLE事件。
- ISR到RcTask的512字节软件环缓冲和任务通知。
- 最大64字节有界CRSF状态机、长度检查和CRC-8/DVB-S2。
- `0x16` 16路11-bit通道及微秒换算。
- `0x14` 上/下行RSSI、LQ、SNR和射频状态。
- 原子RC快照、接收tick、序号、解析/UART/DMA错误计数。
- UART错误的任务上下文Abort/重启恢复。
- UART4 1 Hz通道、链路、错误和RcTask栈摘要。

明确未实现：通道映射/端点参数、App Receiver页面、超时Failsafe、ARM、遥测回传、
FlightTask、PID、DShot或有效电机输出。

## 2. 软件验证结果

### 2.1 离线CRSF回归

运行位置：仓库根目录。

```powershell
node Tools/verify_crsf.mjs
```

结果：PASS。覆盖26字节0x16帧、16路round-trip、微秒换算、0x14有符号字段、噪声、
非法长度、CRC错帧以及下一合法帧恢复。

### 2.2 回归与构建

```powershell
node Tools/verify_attitude_estimator.mjs

node Tools/verify_imu_filter.mjs
```

## 3. 烧录前安全条件

1. 拆除全部螺旋桨。
2. 断开Motor动力电源，只保留飞控、CR8、UART4、USB和SWD所需供电。
3. 确认CR8 TX接PA3/RX2、CR8 RX接PA2/TX2，电平非反相并可靠共地。
4. 使用Debug镜像并记录完整UART4 1 Hz摘要。
5. 不通过交换通道或修改解析器来掩盖发射机通道映射问题；S3.7只报告线序通道1～16。

- [ ] `overflow=0`，UART `err/recover`不持续增长。

### 4.3 Link Statistics

- [ ] `rc link=1`且`link_frames`持续增长。
- [ ] Uplink RSSI为合理负dBm值，两个天线字段无符号反转。
- [ ] LQ位于0～100，近距离稳定连接时保持高值。
- [ ] SNR能显示正负值，不被错误解释为0～255。
- [ ] active antenna、RF mode和power随接收机状态合理更新。
- [ ] Downlink字段存在时取值合理；设备未提供时不会影响通道快照。

### 4.4 断链边界确认

- [ ] 关闭发射机或断开RF链路后，0x16通道帧停止且 `age_ticks`持续增加。
- [ ] S3.7的 `channels_valid`保持最后一次合法帧状态，这是当前冻结设计，不误报为已实现Failsafe。
- [ ] 恢复链路后序号继续增长，通道与Link Statistics恢复更新。
- [ ] 全程Motor GPIO保持安全低电平。

说明：超时后撤销RC有效性、进入Failsafe以及禁止自动重新ARM属于S3.8验收，不得用本节
替代S3.8安全关口。

### 4.5 UART错误恢复

- [ ] 在安全条件下制造一次接收异常或短暂断开信号线，系统无HardFault/重启。
- [ ] 若HAL报告UART错误，`err`增加且RcTask完成恢复，`uart`重新为1。
- [ ] 恢复后CRC帧同步和通道序号继续更新。
- [ ] 软件环缓冲不溢出；若出现溢出，必须定位原因后重新验收。
