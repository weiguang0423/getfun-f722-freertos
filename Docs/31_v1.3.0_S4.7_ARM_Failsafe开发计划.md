# v1.3.0 S4.7 ARM、PREARM与统一Failsafe开发计划

## 1. 本轮范围与来源策略

S4.7由项目完全自主实现，不引入第三方代码或依赖。状态语义与MSP投影只对照项目已经固定的
[Betaflight `4146538b5`源码树](https://github.com/betaflight/betaflight/tree/4146538b5)，
保留本项目已经验收的CRSF Failsafe、`arming_inhibit_flags`和DShot600驱动作为唯一输入/输出事实。

本轮交付：

- 强制PREARM安全握手、DISARMED、ARMED和FAILSAFE四态状态机。
- 汇总所有既有inhibit、输入新鲜度、系统故障、Configurator禁用、控制有效性与DShot状态。
- 仅在ARMED时把S4.6 Mixer逻辑值映射到DShot600。
- ARM飞行输出与S4.3显式Motor Test严格互斥。
- UART和GETFUN MSP2 `0x4009`发布状态、原因和转换计数。
- MSP校准入口、ImuTask校准启动和最终写入点三重拒绝ARMED校准/擦写参数Flash。

不包含：可配置独立PREARM AUX、ANGLE外环、App Modes/PID/Motors写入与参数保存；它们仍分别
属于S4.8/S4.9。当前PREARM是不可关闭的安全握手，不是一个新的AUX通道。

## 2. 状态机契约

| 当前状态 | 条件 | 下一状态 | 电机输出 |
|---|---|---|---|
| PREARM | ARM低位且全部block为0 | DISARMED | 0 |
| PREARM | ARM高位或任一block存在 | PREARM | 0或显式Motor Test |
| DISARMED | 新ARM高位且全部block为0 | ARMED | Mixer映射值 |
| DISARMED | 任一block出现 | PREARM | 0或显式Motor Test |
| ARMED | ARM低位 | DISARMED | 立即为0 |
| ARMED | 任一Failsafe原因出现 | FAILSAFE | 立即为0并锁存原因 |
| FAILSAFE | ARM仍高位 | FAILSAFE | 0 |
| FAILSAFE | ARM低位 | PREARM | 0 |

启动状态固定为PREARM。上电时ARM已经高位不能解锁；Failsafe恢复后也不能自动重解锁，必须先
看到ARM低位，再从DISARMED接受一次新的ARM请求。

## 3. 统一原因位

| 位 | 名称 | 阻止ARM | ARMED时进入FAILSAFE |
|---:|---|:---:|:---:|
| 0 | `IMU_INVALID` | 是 | 是 |
| 1 | `IMU_STALE` | 是 | 是 |
| 2 | `RC_INVALID` | 是 | 是 |
| 3 | `RC_STALE` | 是 | 是 |
| 4 | `ARMING_INHIBITED` | 是 | 是 |
| 5 | `DSHOT_NOT_READY` | 是 | 是 |
| 6 | `CONFIGURATOR_DISABLED` | 是 | 是 |
| 7 | `SYSTEM_FAULT` | 是 | 是 |
| 8 | `CONTROL_INVALID` | 是 | 是 |
| 9 | `THROTTLE_HIGH` | 是 | 否，飞行中高油门是正常输入 |
| 10 | `MOTOR_TEST_ACTIVE` | 是 | 否，Motor Test不允许与ARMED共存 |

`arming_inhibit_flags`的bit 0～7仍由各数据生产者原子维护；S4.7不复制传感器判断逻辑，
FlightTask只把它与5 ms IMU、300 ms RC、DShot、系统故障和控制输出有效性汇总。

## 4. ARM条件与输出所有权

进入ARMED同时要求：

- ARM开关先低后高，Throttle不大于5%。
- RC通道有效且未Failsafe，IMU/姿态/滤波/时间均有效且新鲜。
- `arming_inhibit_flags == 0`，系统故障标志为0。
- Configurator没有请求禁止解锁。
- 当前为RATE模式，Rate PID和Quad-X Mixer输出有效。
- DShot已READY且未锁存DMA/提交故障，没有Motor Test请求。

输出只允许三种来源：

| 条件 | DShot提交值 |
|---|---|
| ARMED | `round(48 + mixer * (2047 - 48))` |
| 非ARMED且显式Motor Test有效 | `0`或工具限制范围内的测试值 |
| 其他情况 | `0` |

ARMED时任一次DShot提交失败会立即调用`dshot_motor_force_safe()`；DMA错误仍由IRQ先拉低GPIO并锁存，
FlightTask最迟在下一周期转入FAILSAFE。Motor Test继续保留250 ms刷新超时和原有两次提交失败保护。

## 5. 状态与诊断

`app_state.flight`新增：

- `arming_state`、`armed`、`arming_block_flags`和`last_failsafe_flags`。
- ARM、正常DISARM和Failsafe累计次数。

UART4新增：

```text
arming state=... armed=... arm_req=... block=0x... last_fs=0x... count=arm/disarm/failsafe inhibit=0x...
```

GETFUN MSP2 `0x4009`固定42字节：版本/状态/标志/DShot、四组原因位、三组转换计数、
Throttle千分值和四路实际DShot值。标准`MSP_STATUS`的mode bit 0同步投影ARMED；非零Motor Test
写入在ARMED或ARM请求高位时直接拒绝。

加速度校准命令在ARMED时由MSP入口拒绝；ImuTask在开始校准和`parameter_store_save()`前
分别读取轻量ARM状态，已ARMED则拒绝启动或保留候选等待安全状态，避免命令接收与状态转换竞态。

- S4.4～S4.6、DShot、姿态、IMU、CRSF、RC Failsafe和电源回归全部继续通过。
- Debug/Release构建链接通过，PARAM_A/PARAM_B仍为0 B，源文件/文档`git diff --check`通过。

软件通过后只标记为“软件完成，待联合实物”。S4.5、S4.6和S4.7按文档32一起验收；通过前不创建
