# S7.2 `rknn-mediapipe` 模型基线验收记录

## 1. 当前结论

> 结论：✅ S7.2完成。
>
> 验收日期：2026-08-13。
>
> 边界：只证明固定TFLite两级模型可在PC运行且输出可重复，不代签S7.3 RKNN转换或板端验收。

开发者指定 [w13364/rknn-mediapipe](https://github.com/w13364/rknn-mediapipe.git) 作为本项目
S7.2手部检测与关键点模型来源，并明确不把许可证作为本阶段关口。本阶段已经完成精确提交、
模型文件、PC参考程序、完整测试集和三次重复输出冻结。

可以冻结的事实：

- 上游默认分支为`master`，本次候选提交为
  `7f03ddcf23cd918bb3e63e92c5156db3d98e6fb6`，提交时间为
  `2025-12-15T09:58:45+08:00`。
- 候选链路是“192×192掌部检测 -> 旋转/缩放ROI -> 224×224手部关键点”的两级结构。
- 上游同时提交了TFLite源候选和RKNN产物；S7.2只把TFLite与前后处理作为PC参考候选，
  上游`.rknn`只作对照样本，不直接视为本项目RK3568可交付模型。
- 上游只在系统临时目录拉取；飞控仓库只保留独立PC参考程序和验收结果，不复制第三方模型。

已知边界：

- 上游文档明确提示`.rknn`必须按自己的开发板重新转换，因此其现成RKNN文件不能跳过S7.3。
- 固定测试集的20张无手图中，`no_hand/no_hand_20.jpg`在当前阈值下产生1次当前帧误检；这是
  S7.5必须用时序确认、未知态和退出门槛隔离的模型输入边界，不允许直接变成RC动作。
- 错误输入中的翻转、旋转、低清和文字叠加图片仍可能被正确识别为手；“错误输入拒绝”只要求
  文件损坏/无法解码时输出`valid=false`，不能把可解码的变换图强制判为无手。

## 3. 当前代码表达的模型契约

### 3.1 掌部检测

| 项目 | 当前候选契约 |
|---|---|
| 输入 | NHWC，`[1, 192, 192, 3]` |
| 颜色 | OpenCV读入BGR后，由入口转换为RGB |
| 数据类型/范围 | `float32`，像素除以255，范围`[0, 1]` |
| 尺寸处理 | 等比例缩放并填充到192×192，保存scale和pad用于坐标还原 |
| 输出0 | 回归张量，候选形状`[1, 2016, 18]`：框4值 + 7个二维关键点 |
| 输出1 | 分类logit，候选形状`[1, 2016, 1]`，经裁剪、sigmoid和加权NMS |
| 锚点 | 2016个，4层，stride为`8/16/16/16` |
| ROI参数 | `kp1=0`、`kp2=2`、`theta0=π/2`、`dscale=2.6`、`dy=-0.5` |
| 阈值 | 掌部检测`0.75`，加权NMS IoU`0.3`；只在参考程序顶部`CONFIG`定义 |

### 3.2 手部关键点

| 项目 | 当前候选契约 |
|---|---|
| 输入 | 旋转/缩放ROI，NHWC，`[1, 224, 224, 3]` |
| 颜色与范围 | RGB，`float32`，`[0, 1]` |
| 输出0 | 21个三维关键点，共63值 |
| 输出1 | 手存在/关键点置信度，1值 |
| 输出2 | 左右手分数，1值；实测`>0.5`对应测试集的右手、`<=0.5`对应左手，按模型观察者视角冻结 |
| TFLite额外输出 | 上游下载脚本还描述一个63值world-landmark输出，但当前C++ RKNN路径只取前三个输出 |
| 坐标还原 | ROI逆仿射把x/y映回原图；z保持模型深度语义 |

LiteRT 2.1.6运行时查询已证明上述输入输出；关键点模型还有`Identity_3 [1,63]`世界坐标输出，
S7.2不使用。完整名称、索引、形状、类型和量化参数见`Tools/s7_2/validation/run1/environment.json`。

## 4. 上游一致性审查

以下差异必须在本项目参考实现中明确取舍，不能原样继承后再凭结果猜测：

1. `Config.cpp`的掌部阈值是`0.5`，单图、视频和摄像头入口又设置为`0.75`。
2. `Makefile.blaze_tflite`仍编译当前RKNN版`Detector.cpp`和`Landmark.cpp`，却链接
   TensorFlow Lite，不能视为已提供可运行的PC参考链。
3. `rknn.py`引用仓库中不存在的`hand_detector_3576.rknn`和
   `hand_landmarks_detector_3576.rknn`，并把关键点置信度简化为固定`1.0`，不能作为基准真值。
4. README单图命令使用不存在的`8.jpg`，仓库实际提交的是`9.jpg`和`photo.jpg`；现有图片也
   不覆盖无手、遮挡、边缘、距离、角度和光照组合。
5. 视频/摄像头帮助文字仍显示TFLite默认文件名，而实际参数默认值是RKNN文件名。
6. 左右手标签还未证明是否以镜像画面、相机视角或人物自身视角解释；在固定镜像策略前，
   `>0.5 -> left`不能直接成为项目语义。
7. 上游构建文件使用本机`g++`、固定`/usr/include/opencv4`及系统RKNN库路径；它只可作为
   板端原生构建线索，不能证明当前RK3568 SDK、Runtime 1.3.0或交叉工具链兼容。

## 6. PC参考输出冻结格式

PC程序对每个输入输出一条JSON Lines记录，至少包括：

```text
sample_sha256, frame_index, detector_input_shape, detector_score,
bbox_xyxy_normalized, detector_keypoints_7x2, roi_center_scale_rotation,
landmark_input_shape, presence_score, handedness_score,
landmarks_21x3_roi, landmarks_21x3_image, valid, reject_reason
```

同时保存可视化图或视频，但机器可比较的JSONL才是S7.3误差对照基准。浮点输出采用固定小数位，
排序规则固定；重复运行不得因未初始化内存、遍历顺序或时间戳改变模型结果字段。

参考程序是`Tools/s7_2/s7_2_pc_reference.py`。它无跨帧状态：每个文件/帧都重新构造完整结果；
解码失败直接输出`valid=false, reject_reason=invalid_image`，不存在沿用旧框或旧关键点的路径。
