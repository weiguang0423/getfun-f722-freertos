# GETFUN F722 V3 v0.4.0 陀螺静态零偏校准开发计划

> 基线：`v0.3.0-imu-dma-drdy-baseline`（`67e38ea`）<br>
> 目标里程碑：`v0.4.0-gyro-calibration-baseline`<br>
> MCU：STM32F722RET6<br>
> 日期：2026-07-29<br>
> 当前状态：开发者于2026-07-30确认实物验收通过，允许冻结目标里程碑

## 1. 本轮开发定位

v0.3.0已经冻结以下可靠链路：

```text
ICM42688P
  → 1 kHz DRDY寄存器门控
  → SPI1 DMA读取14字节样本
  → SI单位换算
  → CW90机体系变换
  → app_state / MSP_RAW_IMU
```

当前 `angular_rate_rad_s[]` 仍包含每次上电、温度和器件个体引起的静态零偏。
如果直接进入滤波、姿态或PID，零偏会造成姿态积分漂移和错误控制量。因此v0.4.0只增加
陀螺静态零偏校准，先建立后续姿态与控制链共同依赖的校准边界。

本轮数据链固定为：

```text
原始寄存器
  → SI单位
  → CW90机体系
  → 上电静态零偏估计
  → 机体系角速度减去零偏
  → app_state / MSP / 后续FlightTask
```

零偏必须在 `CW90` 之后计算和保存，禁止在驱动层、MSP层和未来控制器中重复修正轴向。

## 2. 预期达成目标

1. 增加不依赖HAL/RTOS的纯算法模块 `gyro_calibration`。
2. IMU每次成功初始化后自动进入校准。
3. 只有连续静止样本才允许形成校准窗口。
4. 使用在线均值与方差判断窗口质量，不保存2000帧历史数组。
5. 校准完成后冻结三轴机体系零偏，并从后续角速度中扣除。
6. 运动、无效值或方差超限时丢弃当前窗口并重新等待静止。
7. IMU连续三次读失败离线后清除校准状态；恢复初始化后重新校准。
8. `app_state`发布状态、进度、零偏和拒绝统计。
9. IMU未在线或陀螺未校准时设置独立解锁抑制位。
10. UART 1 Hz摘要能够直接观察校准过程。
11. 保持v0.3.0的SPI、DMA、ODR、量程、坐标、MSP缩放和Motor安全基线。

## 3. 固定算法参数

| 参数 | 固定值 | 作用 |
|---|---:|---|
| 输入角速度单位 | rad/s | 与现有内部SI单位一致 |
| 输入加速度单位 | m/s² | 用于静止合理性检查 |
| 预热样本 | 250 | 要求约0.25秒连续静止 |
| 均值/方差样本 | 2000 | 要求约2秒连续静止 |
| 理论最短校准时间 | 2.25秒 | 以1 kHz新样本计 |
| 单轴瞬时角速度上限 | 5 deg/s | 超限视为运动 |
| 加速度模长范围 | 0.8 g～1.2 g | 超范围视为运动或异常 |
| 单轴窗口标准差上限 | 0.5 deg/s | 超限丢弃窗口 |
| 零偏保存坐标系 | `CW90`后的机体系 | 后续算法直接使用 |
| 零偏持久化 | 不启用 | 每次上电重新估计 |

当前没有设置“校准总超时”。持续移动时状态保持 `CALIBRATING`，直到得到合格静止窗口；
这比超时后错误放行更安全。未来ARM逻辑必须以 `READY` 为必要条件。

## 4. 状态机

### 4.1 状态定义

| 值 | 状态 | 含义 |
|---:|---|---|
| 0 | `NOT_STARTED` | IMU未初始化或已经离线 |
| 1 | `CALIBRATING` | 等待/累计连续静止窗口 |
| 2 | `READY` | 零偏已冻结并开始扣除 |

### 4.2 状态转换

```text
IMU未初始化/离线
        │ initialize成功
        ▼
CALIBRATING
  ├─ 运动/无效值/方差超限 ──→ 清空窗口，仍为CALIBRATING
  ├─ 250预热 + 2000稳定样本 ─→ READY
  └─ IMU连续三次读失败 ─────→ NOT_STARTED

READY
  ├─ 普通机体运动 ──────────→ 保持READY，零偏不再学习
  └─ IMU离线/重新初始化 ────→ NOT_STARTED → CALIBRATING
```

READY后禁止继续自适应零偏，否则飞行中的真实低速角运动可能被错误吸收到零偏中。

## 5. 算法实现

### 5.1 连续静止门限

每个新样本先检查：

- 六个输入浮点值全部有限。
- 三轴角速度绝对值均不超过5 deg/s。
- 三轴加速度模长位于0.8 g～1.2 g。

任一条件失败就清空预热和稳定窗口。运动样本数、无效样本数和丢弃过部分进度的重启次数
分别累计并使用饱和计数，不能溢出回零。

### 5.2 Welford在线统计

稳定窗口对每个轴维护：

```text
count
mean
M2
```

新样本 `x`：

```text
delta = x - mean
mean  = mean + delta / count
M2    = M2 + delta * (x - mean)
```

窗口结束时：

```text
variance = M2 / (count - 1)
```

这种方法只需固定大小状态，不需要8 KB以上的历史浮点数组，也比直接累计平方和更不容易
受浮点相消影响。

### 5.3 零偏应用

- `CALIBRATING`期间继续发布当前对齐后的角速度，便于MSP和UART观察运动。
- 变为 `READY` 的同一帧开始发布 `aligned_rate - bias`。
- 加速度和温度不在本轮校准。
- 零偏只保存于RAM；重新上电和IMU完整恢复都会重新计算。

## 6. 模块与接口

新增：

```text
APP/Inc/algorithms/gyro_calibration.h
APP/Src/algorithms/gyro_calibration.c
```

接口：

```c
void gyro_calibration_reset(gyro_calibration_t *calibration);
void gyro_calibration_start(gyro_calibration_t *calibration);
gyro_calibration_state_t gyro_calibration_process(
    gyro_calibration_t *calibration,
    const float angular_rate_rad_s[3],
    const float acceleration_m_s2[3]);
void gyro_calibration_apply(
    const gyro_calibration_t *calibration,
    const float angular_rate_rad_s[3],
    float corrected_rad_s[3]);
```

约束：

- 算法模块不得访问SPI、HAL Tick、FreeRTOS、app_state或日志。
- 上下文由ImuTask静态持有，不使用动态内存。
- `process()`每个有效新样本只调用一次。
- `apply()`允许输入与输出使用同一数组。

## 7. app_state与安全边界

`app_imu_sample_t`新增：

```c
app_gyro_calibration_state_t gyro_calibration_state;
uint16_t gyro_calibration_sample_count;
uint32_t gyro_calibration_restart_count;
uint32_t gyro_calibration_motion_reject_count;
uint32_t gyro_calibration_invalid_sample_count;
float gyro_bias_rad_s[3];
```

全局快照新增：

```c
uint32_t arming_inhibit_flags;
```

固定标志：

| 位 | 名称 | 置位条件 |
|---:|---|---|
| 0 | `APP_ARMING_INHIBIT_IMU_NOT_READY` | IMU不在线 |
| 1 | `APP_ARMING_INHIBIT_GYRO_NOT_CALIBRATED` | 校准状态不是READY |

`app_state_publish_imu()`在同一个短临界区内复制IMU快照并更新这两个标志，避免消费者读到
“校准READY但解锁抑制尚未清除”的半状态。现有 `configurator_arming_disabled` 只表示宿主
下发状态，不能被复用为传感器安全条件。

本轮尚未实现真实ARM/DISARM状态机；后续ARM逻辑必须同时检查所有
`arming_inhibit_flags`。

## 8. ImuTask接入顺序

每个有效DMA样本：

1. 器件层完成14字节解析。
2. 转换加速度、角速度和温度到SI单位。
3. 对加速度和角速度执行 `CW90` 机体系变换。
4. 把对齐后的角速度和加速度交给 `gyro_calibration_process()`。
5. 调用 `gyro_calibration_apply()`；READY时扣除零偏。
6. 同步校准状态、进度、计数和零偏到 `app_imu_sample_t`。
7. 更新样本/DMA统计并整体发布app_state。

初始化、DRDY查询和DMA错误路径保持v0.3.0行为。单次读错误不清除已经完成的校准；
只有连续三次错误导致IMU离线时才清除，完整恢复后重新校准。

## 9. UART诊断

新增1 Hz摘要：

```text
imu cal=1 progress=.../2000 restart=... motion=... invalid=...
    inhibit=0x00000002 bias_mrad_s=[0,0,0]
```

静止校准完成后应变为：

```text
imu cal=2 progress=2000/2000 ... inhibit=0x00000000
    bias_mrad_s=[...,...,...]
```

状态变化说明：

- `cal=0`：IMU尚未成功初始化或已经离线。
- `cal=1`：正在等待连续静止窗口。
- `cal=2`：零偏已冻结并应用。
- `motion`增加：存在不满足静止门限的样本。
- `restart`增加：已经积累的部分窗口被丢弃。
- `invalid`增加：输入出现NaN/Inf；正常传感器数据不应发生。

## 11. 本轮不包含

- 加速度零偏、比例或六面校准。
- 校准参数Flash持久化。
- 温度补偿或运行中自适应零偏。
- 软件低通、Notch或RPM Filter。
- 微秒时间戳和精确 `dt`。
- Mahony姿态、CRSF、PID、Mixer或DShot。
- GPIO DRDY/EXTI；当前仍没有IMU INT引脚证据。
- 任何有效电机波形。
