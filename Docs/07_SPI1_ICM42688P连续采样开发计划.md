# GETFUN F722 V3 ICM42688P 连续采样开发计划

> 基线：`v0.1.0-platform-baseline`  
> 目标里程碑：`v0.2.0-imu-polling-baseline`  
> 软件执行状态：已实现，等待实物验收  
> 安全要求：全程拆除螺旋桨，首次测试不连接电机动力电源

---

## 1. 本轮开发定位

`v0.1.0-platform-baseline` 已完成 STM32F722 216 MHz 时钟、FreeRTOS、USB CDC、基础 MSP、平台心跳、故障安全停机以及 Motor 1～8 GPIO 低电平基线。

姿态解算、滤波和控制器都依赖稳定且单位明确的 IMU 数据，因此本轮只建立一条可独立冻结的 IMU 轮询采样链路：

```text
SPI 可通信
  → WHO_AM_I 正确
  → 配置可回读
  → 单次数据合理
  → 1 kHz 连续采样
  → app_state 发布
  → Betaflight App 显示
  → 断线和错误恢复
```

本轮不实现姿态角。Betaflight App 中 ACC/GYRO 原始曲线应可用，但三维姿态模型暂不要求随板卡运动。

## 2. 预期目标

1. 通过 SPI1 稳定识别 ICM42688P。
2. 完成软件复位、1 kHz ODR、陀螺 ±2000 dps、加速度 ±16 g 和 Low Noise 配置。
3. 由静态 ImuTask 以 1 tick 周期连续采集温度、加速度和角速度。
4. 内部统一保存 `m/s²`、`rad/s` 和 `°C`。
5. 应用 `CW90_DEG` 基线坐标变换，并把方向结论保留为实物待确认。
6. 通过完整快照向 MSP 和后续飞控算法提供一致数据。
7. IMU 故障时保留 USB、UART、RTOS 心跳和后台恢复能力。
8. 全过程不引入电机控制，不改变 Motor 1～8 安全低电平。

## 3. 设计思路

### 3.1 先正确，再提高吞吐

首版采用阻塞式 SPI 轮询，不同时引入 DMA、FIFO、D-Cache 一致性、外部中断和双缓冲。14 字节样本在 1.6875 MHz 下传输时间相对于 1 ms 周期足够短，并且逻辑分析仪上的每个事务都能直接对应到驱动调用。

本轮结果将成为后续 DMA/DRDY 版本的正确性参照。后续优化必须保持物理量、轴向和 MSP 显示结果一致。

### 3.2 总线、器件、系统策略分离

```text
imu_bus
    ↓
icm42688p
    ↓
ImuTask
```

- `imu_bus` 只负责 HAL SPI1、PA4 CS、长度限制、5 ms 超时和错误映射。
- `icm42688p` 只负责寄存器、复位、识别、配置回读和原始样本，不依赖 FreeRTOS。
- `ImuTask` 负责周期、重试、单位、坐标、统计和状态发布。

以后切换 DMA 时主要替换总线层；以后增加姿态解算时只读取 `app_state`，不需要了解 SPI 寄存器。

### 3.3 内部使用 SI 单位

原始 ADC 计数依赖量程，MSP 又有历史协议缩放。若把其中任一种保存为系统状态，姿态、滤波和 PID 都会重复处理量程和协议细节。

因此系统内部固定使用：

- 加速度：`m/s²`
- 角速度：`rad/s`
- 温度：`°C`

只有 `MSP_RAW_IMU` 响应边界转换为 Betaflight App 所需整数。

### 3.4 单写者和完整快照

ImuTask 是 ICM42688P 和 IMU 状态的唯一写者。MspTask 与 InitTask 只读取 `app_state`：

```text
ImuTask 读取并转换
    ↓
app_state_publish_imu()
    ↓
完整 app_imu_sample_t 快照
    ├── MspTask：协议转换
    └── InitTask：1 Hz 诊断
```

快照沿用 PRIMASK + DMB 短临界区。临界区内只复制结构体，不调用 SPI、UART、USB、延时或动态分配。

### 3.5 局部故障隔离

CPU Fault、FreeRTOS assert、栈溢出仍属于平台致命故障，进入安全停机。WHO_AM_I 不符、SPI 超时或配置回读失败属于 IMU 局部故障：

- `imu.present=false`
- MSP 清除 ACC/GYRO 位
- UART 保留诊断
- 每 1 秒后台重试
- 电机继续保持安全低电平

未来存在解锁状态机后，`imu.present=false` 必须成为禁止解锁条件。

### 3.6 低频诊断不干扰采样

ImuTask 不输出 UART。InitTask 调整为 `osPriorityIdle`，低于 ImuTask 和 MspTask，每秒读取一次快照并输出：

- 在线状态、WHO_AM_I、驱动错误、总线错误
- 实际样本数与每秒样本率
- 初始化错误、读取错误、Data Ready 未就绪和超期统计
- 三轴加速度、三轴角速度、温度
- ImuTask 栈高水位和配置回读

这样 UART 轮询发送会被 1 kHz ImuTask 抢占，不会让维护日志破坏采样周期。

## 4. 硬件与外设方案

| 项目 | 配置 |
|---|---|
| MCU | STM32F722RET6，216 MHz |
| SPI | SPI1 Master，Full Duplex 2 Lines |
| SCK | PA5 / AF5 |
| MISO | PA6 / AF5 |
| MOSI | PA7 / AF5 |
| CS | PA4，软件 GPIO |
| CPOL/CPHA | Low / 1 Edge，Mode 0 |
| 数据宽度 | 8 bit |
| 位序 | MSB first |
| NSS | Software |
| 分频 | PCLK2 108 MHz / 64 |
| 初始速率 | 1.6875 MHz |
| HAL 超时 | 5 ms |
| DMA/IRQ | 本轮关闭 |

PA4 在 `MX_GPIO_Init()` 中先写高再配置输出。每个事务必须满足：

```text
CS 低 → 地址 + 完整负载 → CS 高
```

所有 HAL 返回路径都必须恢复 CS 高电平。

## 5. ICM42688P 固定配置

| 寄存器 | 地址 | 操作/预期 |
|---|---:|---|
| `DEVICE_CONFIG` | `0x11` | 写 `0x01` 软件复位 |
| `TEMP_DATA1` | `0x1D` | 14 字节批量读取起点 |
| `INT_STATUS` | `0x2D` | 读取 Data Ready bit 3 |
| `PWR_MGMT0` | `0x4E` | 写/回读 `0x0F` |
| `GYRO_CONFIG0` | `0x4F` | 写/回读 `0x06` |
| `ACCEL_CONFIG0` | `0x50` | 写/回读 `0x06` |
| `WHO_AM_I` | `0x75` | 必须为 `0x47` |
| `REG_BANK_SEL` | `0x76` | 写 `0x00` 选择 Bank 0 |

初始化顺序固定：

1. 校验 SPI1 已就绪，并保持 CS 高。
2. 选择 Bank 0。
3. 软件复位并等待 2 ms。
4. 重新选择 Bank 0并读取 WHO_AM_I。
5. 配置 Gyro、Accel 和 Low Noise 电源模式。
6. 等待 45 ms。
7. 回读并逐项比较三个配置寄存器。
8. 执行一次 14 字节预读。
9. 成功后发布在线状态。

## 6. ImuTask 与数据处理

| 项目 | 配置 |
|---|---|
| 创建方式 | `xTaskCreateStatic()` |
| 栈 | 512 words |
| 优先级 | `tskIDLE_PRIORITY + 4` |
| 周期 | `pdMS_TO_TICKS(1)` |
| 调度 | `vTaskDelayUntil()` |
| 初始化尝试 | 每轮 3 次，间隔 10 ms |
| 离线重试 | 1 秒 |
| 运行失效门限 | 连续 3 次读取失败 |

每周期执行：

1. 等待绝对周期点。
2. 计算是否错过周期。
3. 读取 `INT_STATUS`。
4. 未就绪则累计 `data_not_ready_count`。
5. 就绪后单次读取 14 字节。
6. 按大端组合温度、三轴加速度和三轴陀螺。
7. 转换 SI 单位。
8. 应用 `CW90_DEG`。
9. 更新统计并整体发布。

换算：

```text
accel_m_s2 = raw_accel / 2048 × 9.80665
gyro_rad_s = raw_gyro / 16.4 × π / 180
temperature_c = raw_temperature / 132.48 + 25
```

坐标变换：

```text
body_x = sensor_y
body_y = -sensor_x
body_z = sensor_z
```

该方向必须通过六面放置和三轴手动旋转确认。

## 7. 状态和 MSP 接口

`app_imu_sample_t` 保存：

- `present`
- `who_am_i`
- 驱动/总线最后错误
- 三个配置回读值
- `sample_tick`、样本数和各类错误统计
- `acceleration_m_s2[3]`
- `angular_rate_rad_s[3]`
- `temperature_c`

发布接口：

```c
void app_state_publish_imu(const app_imu_sample_t *sample);
```

MSP 规则：

```text
acc_wire =
    round(acceleration_m_s2 / 9.80665 × 2048)

gyro_wire =
    round(angular_rate_rad_s × 180 / π × 16.4 / 4)

mag_wire = 0
```

转换结果必须饱和到 `int16_t`；非有限值返回 0。IMU 离线时 `MSP_RAW_IMU` 返回 9 个 0，`MSP_STATUS/STATUS_EX` 清除 ACC/GYRO 位。

- 所有新增 `.c/.h` 顶部必须说明用途、核心接口、数据流和约束。
- 所有新增 Markdown 必须在标题前说明用途、覆盖范围和实物边界。

## 10. 本轮不包含

- SPI DMA、FIFO、DRDY GPIO 中断。
- 陀螺静态零偏、加速度六面校准和参数持久化。
- 软件低通、陷波和动态滤波。
- 姿态解算、FlightTask、PID、CRSF、DShot。
- 电机解锁或任何有效驱动波形。
