# S7.5 手势集合、置信度与时序状态机开发验收

> 当前状态：🟡 软件首版已实现并通过主机纯逻辑自检；等待冻结环境交叉构建和板端真人验收

## 1. 范围与安全边界

S7.5 只把 S7.4 的单手 21 点观测转换为手势观测和时序状态，不生成虚拟 RC、不发送数据给
STM32、不控制 ARM/PID/Mixer/DShot。S7.4 已验收的二级推理和显示程序保持原构建行为；
`build_board.sh` 通过 `S7_5_GESTURE` 单独生成 `s7_5_live`。

所有手势在本阶段的 RC 语义统一冻结为“无 RC 输出”。`active_gesture_id/name` 只是 S7.6 的
候选意图输入；具体通道、方向、范围、变化率和释放值必须在 S7.6 另行冻结，禁止由手势名称
暗示并提前输出控制量。

## 2. 手势集合与几何定义

复用决策为“官方词汇/关键点契约参考 + 项目最小自主实现”。Google AI Edge 官方
[Gesture Recognizer 选项](https://ai.google.dev/edge/api/mediapipe/python/mp/tasks/vision/GestureRecognizerOptions)
登记了 `Closed_Fist`、`Open_Palm`、`Pointing_Up`、`Victory` 等预置类别；官方
[HandLandmark 枚举](https://ai.google.dev/edge/api/mediapipe/python/mp/tasks/vision/drawing_styles/hand_landmarker/HandLandmark)
登记了本项目所用 0～20 关键点语义（访问日期 2026-08-17）。S7.5 只参考其中四类易区分词汇和
21 点编号，不引入 MediaPipe Tasks、额外 TFLite 手势模型或第三方源码：现有 RKNN 链已经输出
所需关键点，而新增长运行库/模型会扩大 S7.3 已冻结转换与板端误差验收范围。当前实现名称按
项目输出简化为 `FIST/OPEN_PALM/POINT/V_SIGN`，阈值与时序安全逻辑完全由项目掌握。

| ID | 机器名 | 用户含义 | 几何条件 | 冲突结果 |
|---:|---|---|---|---|
| 1 | `OPEN_PALM` | 张掌 | 拇指、食指、中指、环指、小指均伸展 | 与次优类别差值不足时 `UNKNOWN` |
| 2 | `FIST` | 握拳 | 五指均弯曲 | 半握或关节不稳定时 `UNKNOWN` |
| 3 | `POINT` | 单指 | 食指伸展，中/环/小指弯曲；拇指不参与硬判定 | 与 V 字冲突时按得分和差值门槛拒绝 |
| 4 | `V_SIGN` | V 字 | 食指、中指伸展并分开，环指、小指弯曲 | 分离度不足时 `UNKNOWN` |

分类使用图像归一化 `x/y`，不依赖相机中的绝对尺寸。四指伸展度由 PIP/DIP 关节直线度和
MCP 到指尖的弦长/骨节链长共同计算；拇指另加入指尖到食指 MCP 相对掌宽。第一候选几何得分
必须不低于 0.58，且领先第二候选至少 0.08；最终 `gesture_confidence` 是几何得分与
`presence_score` 的较小值。输入非有限、掌宽退化或不满足门槛统一输出 ID 0 `UNKNOWN`。

当前模型只输出单个最高分手框，因此多手不尝试仲裁：无法稳定落入上述唯一定义即
`UNKNOWN`。左右手使用同一距离/角度几何规则，不把可能存在误差的 handedness 当作分类门禁。

## 3. 时序状态机

| 项目 | 冻结值 |
|---|---:|
| ACTIVE 最低置信度 | 0.75 |
| 连续确认 | 同一手势 5 帧且跨度至少 150 ms |
| 最大相邻输入间隔 | 250 ms |
| 释放冷却 | 300 ms |

状态语义：

- `NO_HAND`：当前无有效手。
- `UNKNOWN`：有有效手，但类别未知或低于 ACTIVE 门槛。
- `CANDIDATE`：唯一手势正在连续确认；`active_gesture_id` 仍为 0。
- `ACTIVE`：确认完成，唯一允许暴露非零活动手势的状态。
- `RELEASED`：曾经的 ACTIVE/CANDIDATE 因失效、切换或超时释放，冷却期内禁止重激活。

无手、低置信度、未知、采集/推理失败、坏帧、deadline miss、超过 250 ms 未更新或从一个
活动手势切到另一个手势，都会在当前输出把 `active_gesture_id/name` 清为 `0/UNKNOWN`；不得
保留上一次动作。进程启动时没有历史状态。

## 4. 输出与观测

S7.5 在 S7.4 每帧 JSON 后新增：`gesture_id/name`、`gesture_confidence`、`gesture_state`、
`active_gesture_id/name` 和 `candidate_frames`。屏显同步叠加逐帧观测、置信度、状态和活动手势；
只有 `ACTIVE` 使用绿色状态文字，其他状态使用橙色。

`evaluate_results.py` 读取人工标注的驱动序号区间和板端 JSONL，输出：

- `expected x active` 混淆矩阵；
- 每个重复手势区间从首帧到首次 ACTIVE 的进入延迟；
- 无标签或标为 `UNKNOWN` 区间内的误触发总数及序号。
