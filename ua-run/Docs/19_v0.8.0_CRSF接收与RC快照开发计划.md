# v0.8.0 CRSF接收与RC快照开发计划

> 版本目标：`v0.8.0-crsf-rc-baseline`  
> 所属里程碑：S3.7  
> 基线：`v0.7.0-mahony-attitude-baseline`  
> 当前状态：软件完成，待真实硬件验收

## 1. 当前事实与需求

板卡硬件文档已经冻结：CR8 TX接飞控PA3/RX2，CR8 RX接PA2/TX2，共地并由5 V供电。
现有v0.7.0只有UART4诊断口，没有USART2初始化、DMA接收、RcTask或RC运行态快照。

S3.7要建立的链路是：

```text
CR8 ELRS -> USART2 RX -> DMA1 Stream 5循环缓冲 -> ISR搬运/通知
          -> RcTask CRSF校验与解码 -> app_state.rc一致快照
          -> UART4 1 Hz摘要
```

完成后，后续FlightTask和S3.8只能读取快照，不能直接读取DMA缓冲区。

## 2. 协议依据与实现来源

协议以TBS维护的CRSF公开规范为主要依据：

- 帧最大64字节；长度字段不含地址与长度字节，有效范围2～62。
- CRC覆盖Type与Payload，使用CRC-8/DVB-S2多项式 `0xD5`。
- 飞控地址为 `0xC8`。
- `0x16` 使用22字节承载16路11-bit通道，中心值992。
- `0x14` 使用10字节承载上/下行RSSI、LQ、SNR及射频状态。

参考：<https://github.com/tbs-fpv/tbs-crsf-spec/blob/main/crsf.md>（2026-08-04核对）。
CR8属于ExpressLRS接收机，本项目遵循既有硬件基线使用420000 baud 8N1；该值也与
ExpressLRS飞控串口常用默认配置一致。协议解析器为项目自主编写的有界纯C模块，没有
复制或引入第三方源码。

## 3. UART2与DMA设计

| 项目 | 冻结值 |
|---|---|
| UART | USART2，PA2 TX / PA3 RX |
| 串口格式 | 420000 baud，8N1，非反相，全双工引脚 |
| RX DMA | DMA1 Stream 5 / Channel 4 |
| DMA模式 | Circular，byte对齐，memory increment |
| DMA缓冲 | 128字节 |
| 软件环缓冲 | 512字节，单ISR写者/单RcTask读者 |
| 事件 | UART IDLE、DMA Half Transfer、Transfer Complete |
| 中断优先级 | 5，可调用FreeRTOS `...FromISR` API |

ISR只计算DMA新写位置、复制新增字节、累计计数并通知RcTask。CRC、通道解包、状态发布、
日志格式化和错误恢复不在ISR执行。UART阻塞错误由ISR记录并请求恢复，RcTask上下文执行
Abort与重新启动Receive-to-IDLE DMA。

## 4. CRSF解析器契约

解析器逐字节处理并保持固定64字节内部缓冲：

1. 等待飞控地址 `0xC8`。
2. 检查长度2～62；非法长度立即丢弃并重新同步。
3. 收满 `length + 2` 字节后计算CRC。
4. CRC错误只增加错误计数，不发布Payload。
5. 合法但暂不支持的帧只增加unsupported计数，不破坏后续同步。
6. Payload比当前已知结构更长时只读取已知前缀，允许协议向后扩展。

`0x16` 按LSB-first位流解出16个11-bit值，同时保存：

```text
raw[i]      = 0..2047协议值
channel_us  = 1500 + (raw - 992) * 5 / 8
```

不在S3.7执行AETR/TAER映射、端点裁剪、Deadband或归一化，这些属于S3.8/S4.4。

## 5. RC快照契约

`app_state.rc`由RcTask单写并通过短临界区整体发布，包含：

- `channels_valid`、`last_channel_tick`、`channel_sequence`。
- 16路 `channel_raw[]` 与 `channel_us[]`。
- `link_statistics_valid`、最后链路帧tick及完整0x14字段。
- 合法帧、CRC、长度、payload、unsupported和sync drop计数。
- UART启动、事件、IDLE、环溢出、错误、恢复和最后HAL错误。

`channels_valid=true`只表示至少收到过一帧合法0x16数据。S3.7不会因为数据变旧而把它
改回false；消费者必须同时查看接收tick。S3.8将冻结超时阈值、Failsafe状态和恢复策略，
从而避免本阶段暗中决定安全语义。

## 6. 任务与资源

RcTask使用静态512-word栈，优先级 `tskIDLE_PRIORITY + 3`，低于ImuTask、高于MspTask。
正常情况下由UART/DMA通知唤醒，20 ms超时只用于错误恢复和诊断发布。禁止动态内存。

新增源文件：

- `APP/Inc|Src/protocol/crsf.*`
- `APP/Inc|Src/bsp/crsf_uart.*`
- `APP/Inc|Src/rtos/rc_task.*`
- `Tools/verify_crsf.mjs`

修改USART2/DMA/NVIC初始化、全局app_state、任务创建、UART4诊断、CMake和CubeMX `.ioc`。

## 7. 离线与构建验证

独立脚本必须覆盖：

- CRC-8/DVB-S2已知算法路径。
- 16路跨字节11-bit打包/解包。
- 172/992/1811到约988/1500/2011 us换算。
- 噪声前缀、非法长度、CRC错帧和下一帧恢复。
- Link Statistics有符号RSSI/SNR解释。

ARM Debug/Release构建负责验证C实现、HAL接口、中断符号、FPU ABI、链接区和镜像生成。
