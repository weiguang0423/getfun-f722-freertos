# 从 21 个关键点得到可靠手势

> **文档进度：`摄像头与关键点 → [本篇：单帧几何分类 + 跨帧状态机] → 虚拟RC映射`**
>
> **真实数据流位置：`21×3关键点 + presence → 单帧手势观察 → 连续确认/释放 → ACTIVE手势`**
>
> 本篇只产生“可靠手势状态”。它不打开串口，不生成 RC 通道值，也不让飞控动作。

## 真实问题：一帧看起来像张掌，为什么还不能触发动作

上一篇已经让每个可用画面输出 21 个手部关键点。`valid:true` 只说明“这一帧里有可用的手部观测”，并不表示人的意图已经稳定。

真实摄像头会遇到：

- 手刚进入画面，关键点还在跳；
- 半握拳同时有点像握拳和单指；
- 一帧被遮挡，食指被错误拉直；
- 程序卡顿 300 ms 后才送来下一帧；
- 手已经移开，但若程序沿用旧结果，旧动作仍会存在。

所以本篇必须补两种能力：

```text
21个点
  ↓ 几何分类器：只回答“当前这一帧最像什么”
GestureObservation
  ↓ 时序状态机：连续多久、是否中断、是否冷却
GestureSnapshot
  ↓
只有 state=ACTIVE 且 active_id非UNKNOWN 才能交给下一篇
```

## 先建立关键点编号，不急着说“伸直”

> **当前位置：`已有21个归一化点 → [把点变成可计算的几何关系] → 计算单指伸展度`**
>
> 本节只建立最小数学工具，还不会输出任何手势。

关键点数组按每点 3 个数排列：

```text
点0:  landmarks[0],  landmarks[1],  landmarks[2]
点1:  landmarks[3],  landmarks[4],  landmarks[5]
...
点20: landmarks[60], landmarks[61], landmarks[62]
```

本分类器只使用每个点的 `x/y`，暂不使用 `z`。21 点中：0 是腕部；1～4 是拇指；5～8 是食指；9～12 是中指；13～16 是无名指；17～20 是小指。

### 为什么先定义 `Point`

直接反复写 `landmarks[3*i]` 很容易把 x、y 索引写错。源码先定义：

```cpp
struct Point {
    float x;
    float y;
};
```

- `struct` 把相关数据组合成一个新类型。
- `Point` 表示一个二维点。
- `float` 是单精度小数；这里保存归一化图像坐标。
- `Point` 不保存历史状态，一个对象只代表一个点值。

### 距离函数先完整定义，再被后面的伸展度使用

需求：判断指尖离指根多远。输入是两个 `Point`，输出是非负距离，不修改任何状态。

```cpp
float distance(Point a, Point b) {
    return std::hypot(a.x - b.x, a.y - b.y);
}
```

`std::hypot(dx, dy)` 计算 `sqrt(dx*dx + dy*dy)`，并由标准库处理数值细节。

具体输入走读：`a=(0.1,0.2)`，`b=(0.4,0.6)`，横向差 `-0.3`，纵向差 `-0.4`，距离为 `0.5`。因为坐标已按图像宽高归一化，这个数没有像素单位。

### 关节直线度怎样变成 0～1

需求：一根手指伸直时，相邻三点在中间关节处接近直线；弯曲时夹角变小。输入 `a-b-c` 三个点，输出 0～1，不修改状态。

```cpp
float clamp01(float value) {
    return std::clamp(value, 0.0f, 1.0f);
}

float straightness(Point a, Point b, Point c) {
    const float ux = a.x - b.x;
    const float uy = a.y - b.y;
    const float vx = c.x - b.x;
    const float vy = c.y - b.y;
    const float length = std::hypot(ux, uy) * std::hypot(vx, vy);
    if (length < 1e-6f) return 0.0f;
    const float cosine = (ux * vx + uy * vy) / length;
    const float angle = std::acos(std::clamp(cosine, -1.0f, 1.0f));
    return clamp01((angle - 1.75f) / 1.05f);
}
```

首次出现的写法：

- `const`：这个局部值算出后不再修改。
- `1e-6f`：0.000001，末尾 `f` 表示 float。
- `ux*vx + uy*vy`：二维向量点积，用来求夹角。
- `std::acos`：从余弦得到弧度角。
- `std::clamp`：把值限制在上下界，避免浮点误差让 `acos` 接到略大于 1 的值。

若某段长度接近 0，方向没有意义，函数保守返回 0，而不是除以 0。最后把约 100°～160° 映射到 0～1：越接近直线，结果越大；超过范围会由 `clamp01` 截住。

## 一根手指的“伸展”不能只看一个关节

> **当前位置：`已有距离和直线度 → [组合成每根手指的伸展分数] → 五指数组`**

只看一个关节会误判：手指可能局部看似直，但整体缩在掌心。因此普通四指同时看两部分：

1. 两个关节中较差的直线度；
2. 指根到指尖的直线距离，占整条骨节链长度的比例。

`mcp` 是 metacarpophalangeal joint 的缩写，在这里就是该指的掌指关节索引。食指 `mcp=5`，中指 9，无名指 13，小指 17。

完整定义：

```cpp
float extension(const std::array<Point, 21>& p, int mcp) {
    const float joints = std::min(
        straightness(p[mcp], p[mcp + 1], p[mcp + 2]),
        straightness(p[mcp + 1], p[mcp + 2], p[mcp + 3]));
    const float chain = distance(p[mcp], p[mcp + 1])
                      + distance(p[mcp + 1], p[mcp + 2])
                      + distance(p[mcp + 2], p[mcp + 3]);
    const float reach = chain > 1e-6f
        ? clamp01((distance(p[mcp], p[mcp + 3]) / chain - .55f) / .30f)
        : 0.0f;
    return .65f * joints + .35f * reach;
}
```

- `std::array<Point,21>` 是固定长度数组，长度编译时已知。
- `& p` 表示通过引用读取原数组，不复制 21 个点。
- `?:` 是条件表达式：链长足够才做除法，否则取 0。
- 权重 0.65 和 0.35 表示关节直线度占主要作用，整体伸展距离作补充。

具体走读：若两个关节直线度为 0.9、0.8，`joints=0.8`；指根到指尖距离与链长比经映射得到 `reach=0.7`，最终伸展度为 `0.65×0.8+0.35×0.7=0.765`。

拇指方向与四指不同，源码单独定义 `thumb_extension()`：关节直线度之外，还把拇指尖到食指根的距离除以掌宽。掌宽用点 5 到点 17 的距离衡量，从而减少手离摄像头远近带来的尺度变化。

```cpp
float thumb_extension(const std::array<Point, 21>& p) {
    const float joints = std::min(straightness(p[1], p[2], p[3]),
                                  straightness(p[2], p[3], p[4]));
    const float palm = std::max(distance(p[5], p[17]), 1e-6f);
    const float span = clamp01((distance(p[4], p[5]) / palm - .45f) / .75f);
    return .65f * joints + .35f * span;
}
```

掌宽被限制为至少 `1e-6`，避免退化输入除以 0。这不是把坏输入变好；公共入口还会明确拒绝掌宽过小的手。

### 五指数组第一次形成

前面的函数已经完整定义，现在才能组合调用：

```cpp
std::array<float, 5> finger_extensions(const std::array<Point, 21>& p) {
    return {
        thumb_extension(p),
        extension(p, 5),
        extension(p, 9),
        extension(p, 13),
        extension(p, 17),
    };
}
```

输出数组 `e` 的下标固定为：0 拇指、1 食指、2 中指、3 无名指、4 小指。若得到 `{0.2,0.9,0.1,0.1,0.2}`，它表达“只有食指明显伸展”，但此时还没有调用手势名。

## 四类手势分数怎样竞争，而不是硬猜

> **当前位置：`已有五指伸展数组 → [计算四类得分与领先差值] → GestureObservation`**

### 先定义手势 ID，再定义平均函数和四类规则

四类得分要与固定机器 ID 成对保存，所以 `GestureId` 必须先于得分数组定义：

```cpp
enum class GestureId : uint8_t {
    UNKNOWN = 0,
    OPEN_PALM = 1,
    FIST = 2,
    POINT = 3,
    V_SIGN = 4,
};
```

`enum class` 是带名字的有限取值集合；`uint8_t` 表示底层用 8 位无符号整数。`UNKNOWN=0` 是安全的“不产生已知手势”。

`average()` 接收若干 0～1 分量，先逐个截断再平均。它不保存状态。

```cpp
float average(std::initializer_list<float> values) {
    float sum = 0.0f;
    for (float value : values) sum += clamp01(value);
    return sum / static_cast<float>(values.size());
}
```

`separation` 是食指尖点 8 与中指尖点 12 的距离相对掌宽的分离度；它只参与 V 字手势。左右手镜像不会改变这些距离，因此不把 `handedness_score` 作为硬门槛。

`1-e[i]` 表示“该指越弯曲，分数越高”。现在 `GestureId` 已经定义，四类分数才第一次使用它：

```cpp
const std::array<std::pair<GestureId, float>, 4> scores{{
    {GestureId::OPEN_PALM, average({e[0], e[1], e[2], e[3], e[4]})},
    {GestureId::FIST, average({1-e[0], 1-e[1], 1-e[2], 1-e[3], 1-e[4]})},
    {GestureId::POINT, average({e[1], 1-e[2], 1-e[3], 1-e[4]})},
    {GestureId::V_SIGN, average({e[1], e[2], 1-e[3], 1-e[4], separation})},
}};
```

### 为什么必须比较第一名和第二名

假设四类得分是：

```text
OPEN_PALM 0.61
FIST      0.10
POINT     0.58
V_SIGN    0.25
```

第一名虽超过分类最低分 0.58，但只领先第二名 0.03。两类太接近，输出 `UNKNOWN` 比武断选择张掌更安全。

冻结门槛：

- `kMinClassificationConfidence=0.58`：单帧分类最低分；
- `kMinClassificationMargin=0.08`：第一名至少领先第二名 0.08；
- 最终置信度取 `presence_score` 与最佳几何分数的较小值。

因此模型若只给 `presence=0.60`，即使几何得分 0.95，最终置信度也只有 0.60。

### 先定义单帧输出 `GestureObservation`

内部分类函数需要一种明确的返回类型，所以先定义：

```cpp
struct GestureObservation {
    GestureId id{GestureId::UNKNOWN};
    float confidence{};
};
```

它没有“已经触发”的含义，只记录当前一帧的类别和置信度。默认构造是 `UNKNOWN,0`。

### 内部分类函数必须先完整定义

公共入口稍后会调用 `classify_points()`，所以这里先完整给出它。输入是已经转换好的 21 个二维点和存在分数；输出是单帧 `GestureObservation`；它不保存历史。函数依赖的 `finger_extensions()`、`distance()` 和 `average()` 都已在前文定义。

```cpp
GestureObservation classify_points(const std::array<Point, 21>& points,
                                   float presence_score) {
    const auto e = finger_extensions(points);
    const float palm = std::max(distance(points[5], points[17]), 1e-6f);
    const float separation = clamp01(
        (distance(points[8], points[12]) / palm - .20f) / .45f);
    const std::array<std::pair<GestureId, float>, 4> scores{{
        {GestureId::OPEN_PALM,
         average({e[0], e[1], e[2], e[3], e[4]})},
        {GestureId::FIST,
         average({1-e[0], 1-e[1], 1-e[2], 1-e[3], 1-e[4]})},
        {GestureId::POINT,
         average({e[1], 1-e[2], 1-e[3], 1-e[4]})},
        {GestureId::V_SIGN,
         average({e[1], e[2], 1-e[3], 1-e[4], separation})},
    }};

    auto best = scores.begin();
    float second = 0.0f;
    for (auto it = scores.begin(); it != scores.end(); ++it) {
        if (it->second > best->second) {
            second = best->second;
            best = it;
        } else if (it != best && it->second > second) {
            second = it->second;
        }
    }

    const float confidence = std::min(clamp01(presence_score), best->second);
    if (confidence < 0.58f || best->second - second < 0.08f)
        return {GestureId::UNKNOWN, confidence};
    return {best->first, confidence};
}
```

`std::pair<GestureId,float>` 把一个类别和一个分数绑在一起；迭代器 `best` 指向当前第一名；`it->second` 取得该项分数。具体得分 0.61、0.10、0.58、0.25 时，第一名张掌 0.61，第二名 POINT 0.58，差 0.03，函数返回 UNKNOWN。

### 公共分类入口在第一次调用前完整定义

`classify()` 输入 63 个数的首地址和存在分数；输出 `GestureObservation`；它不保存历史：

```cpp
GestureObservation classify(const float* landmarks, float presence_score) {
    if (!landmarks || !std::isfinite(presence_score)) return {};
    std::array<Point, 21> points{};
    for (int i = 0; i < 21; ++i) {
        if (!std::isfinite(landmarks[3*i]) ||
            !std::isfinite(landmarks[3*i + 1])) return {};
        points[i] = {landmarks[3*i], landmarks[3*i + 1]};
    }
    if (distance(points[5], points[17]) < 1e-5f) return {};
    return classify_points(points, presence_score);
}
```

- `const float*` 是只读指针，指向数组首元素。
- `!landmarks` 检查空指针。
- `std::isfinite` 拒绝无穷大和 NaN；NaN 是“不是有效数字”的浮点特殊值。
- `return {}` 返回默认 `UNKNOWN,0`。
- `classify_points()` 已在本节前半完整定义，因此这里的调用没有跳过内部实现。

现在才进行分类器的第一次概念调用：

```cpp
GestureObservation observation = classify(landmarks_21x3_image, presence_score);
```

假设五指伸展度为 `{0.2,0.9,0.1,0.1,0.2}`，`presence=0.92`，POINT 得分最高且领先第二名至少 0.08，则 `observation.id=POINT`，`confidence=min(0.92, POINT分数)`。这仍只是单帧观察。

## 为什么还需要五态状态机

> **当前位置：`单帧GestureObservation已得到 → [跨帧确认和立即释放] → GestureSnapshot`**

分类器没有记忆。状态机需要长期保存候选手势、候选帧数、候选开始时间、上次更新时间和冷却结束时间。

### 先完整定义状态和输出快照

```cpp
enum class GestureState : uint8_t {
    NO_HAND,
    UNKNOWN,
    CANDIDATE,
    ACTIVE,
    RELEASED,
};

struct GestureSnapshot {
    GestureState state{GestureState::NO_HAND};
    GestureId observed_id{GestureId::UNKNOWN};
    float observed_confidence{};
    GestureId active_id{GestureId::UNKNOWN};
    unsigned candidate_frames{};
};
```

- `NO_HAND`：没有有效手。
- `UNKNOWN`：有手，但单帧类别不够可靠。
- `CANDIDATE`：同一高置信度手势正在累计；不能输出活动手势。
- `ACTIVE`：帧数和时间都满足；唯一允许 `active_id` 非 0 的状态。
- `RELEASED`：刚从候选或活动状态释放，冷却期内禁止重新激活。

`observed_id` 是当前帧看到什么；`active_id` 是状态机真正批准什么。二者不能混用。

### 状态机长期字段与门槛

```cpp
class GestureStateMachine {
public:
    GestureSnapshot update(bool hand_valid,
                           GestureObservation observation,
                           uint64_t now_us);

private:
    void release(uint64_t now_us);

    GestureState state_{GestureState::NO_HAND};
    GestureId candidate_id_{GestureId::UNKNOWN};
    GestureId active_id_{GestureId::UNKNOWN};
    unsigned candidate_frames_{};
    uint64_t candidate_since_us_{};
    uint64_t release_until_us_{};
    uint64_t last_update_us_{};
};
```

- `hand_valid` 来自上一章整条采集/推理/延迟门禁。
- `observation` 是当前帧分类结果。
- `now_us` 是单调时钟微秒，不会因系统校时突然倒退。
- 末尾 `_` 是项目风格，用来标识对象的私有长期字段。
- `update()` 每帧调用一次，返回当前快照并修改对象状态。

冻结门槛：ACTIVE 置信度至少 0.75；同一手势至少 5 帧且跨度至少 150000 us；相邻输入间隔最多 250000 us；释放后冷却 300000 us。

### 释放动作先完整定义

释放必须一次清掉所有可能留下旧意图的字段：

```cpp
void GestureStateMachine::release(uint64_t now_us) {
    state_ = GestureState::RELEASED;
    active_id_ = GestureId::UNKNOWN;
    candidate_id_ = GestureId::UNKNOWN;
    candidate_frames_ = 0;
    candidate_since_us_ = 0;
    release_until_us_ = now_us + 300000;
}
```

具体走读：在 `now_us=1,250,000` 释放，`active_id_` 当场清为 UNKNOWN，冷却截止 `1,550,000`。冷却并不“保持旧动作 300 ms”；旧动作是立即失效，300 ms 只阻止新动作过快重入。

### `update()` 的完整决策顺序

```text
检查时间是否倒退或相邻间隔>250 ms
  └─ 若原来是CANDIDATE/ACTIVE → 立即release
   ↓
当前是否 hand_valid、类别已知、confidence>=0.75
  ├─ 否 → 原候选/活动立即release；其他状态变NO_HAND或UNKNOWN
  ↓ 是
是否仍在RELEASED冷却期
  ├─ 是 → active仍为UNKNOWN
  ↓ 否
是否已经ACTIVE
  ├─ 是且类别改变 → release
  └─ 是且类别相同 → 保持ACTIVE
  ↓ 尚未ACTIVE
类别是否与candidate_id相同
  ├─ 否 → 新候选从1帧、当前时间开始
  └─ 是 → candidate_frames加1
   ↓
帧数>=5 且跨度>=150 ms
  └─ 是 → ACTIVE并公开active_id
```

完整实现：

```cpp
GestureSnapshot GestureStateMachine::update(bool hand_valid,
                                            GestureObservation observation,
                                            uint64_t now_us) {
    const bool gap = last_update_us_ &&
        (now_us < last_update_us_ || now_us - last_update_us_ > 250000);
    last_update_us_ = now_us;
    if (gap && (state_ == GestureState::ACTIVE ||
                state_ == GestureState::CANDIDATE)) {
        release(now_us);
    }

    const bool recognized = hand_valid &&
        observation.id != GestureId::UNKNOWN &&
        observation.confidence >= 0.75f;

    if (!hand_valid || !recognized) {
        if (state_ == GestureState::ACTIVE || state_ == GestureState::CANDIDATE)
            release(now_us);
        else if (state_ != GestureState::RELEASED || now_us >= release_until_us_)
            state_ = hand_valid ? GestureState::UNKNOWN : GestureState::NO_HAND;
        active_id_ = GestureId::UNKNOWN;
    } else if (state_ == GestureState::RELEASED && now_us < release_until_us_) {
        active_id_ = GestureId::UNKNOWN;
    } else if (state_ == GestureState::ACTIVE) {
        if (observation.id != active_id_) release(now_us);
    } else {
        if (observation.id != candidate_id_) {
            candidate_id_ = observation.id;
            candidate_frames_ = 1;
            candidate_since_us_ = now_us;
        } else {
            ++candidate_frames_;
        }
        state_ = GestureState::CANDIDATE;
        if (candidate_frames_ >= 5 && now_us - candidate_since_us_ >= 150000) {
            state_ = GestureState::ACTIVE;
            active_id_ = candidate_id_;
        }
    }

    return {state_,
            hand_valid ? observation.id : GestureId::UNKNOWN,
            hand_valid ? observation.confidence : 0.0f,
            active_id_,
            candidate_frames_};
}
```

现在定义和走读都完整了，才进行第一次状态机调用：

## 用一条逐帧时间线把 5 帧、150 ms、250 ms、300 ms 走透

> **当前位置：`状态机代码已定义 → [具体输入逐帧演算] → 纯逻辑自检`**

假设每帧都是 `OPEN_PALM, confidence=0.90`：

| 帧 | `now_us` | 距候选开始 | `candidate_frames` | 输出状态 | `active_id` |
|---:|---:|---:|---:|---|---|
| 1 | 1,000,000 | 0 ms | 1 | CANDIDATE | UNKNOWN |
| 2 | 1,050,000 | 50 ms | 2 | CANDIDATE | UNKNOWN |
| 3 | 1,100,000 | 100 ms | 3 | CANDIDATE | UNKNOWN |
| 4 | 1,150,000 | 150 ms | 4 | CANDIDATE | UNKNOWN |
| 5 | 1,200,000 | 200 ms | 5 | ACTIVE | OPEN_PALM |

为什么第 4 帧已经跨 150 ms 仍不激活？因为条件是“至少 5 帧 **并且** 至少 150 ms”，两项都必须满足。为什么不是第 5 帧固定激活？若 5 帧在 80 ms 内异常集中，时间条件仍不满足。

下一帧在 1,250,000 us 只有 0.70 置信度：低于 0.75，立即进入 RELEASED，`active_id` 同一帧清零，冷却到 1,550,000。

在 1,400,000 us 即使高置信度 FIST 出现，仍处冷却期，所以保持 RELEASED；不会从旧张掌直接跳到握拳。到 1,600,000 us 若无手，状态变 NO_HAND。

另一条时间线：POINT 已经 ACTIVE，上次更新时间 2,200,000 us，下一条直到 2,500,001 us 才来。间隔 300001 us，大于 250000 us；即使新记录仍是高置信度 POINT，也先释放。状态机不能假设卡顿期间人的手一直没变。

## 纯逻辑自检先于摄像头和 NPU

> **当前位置：`分类和状态机已完整建立 → [最小可重复检查] → 接入实时程序`**

自检不能依赖真人现场重复摆手，否则同一次代码改动很难得到完全相同输入。内部函数 `make_test_hand()` 接收五个布尔值：`true` 表示该指伸展，`false` 表示弯曲；输出 21 个确定性二维点。它只为回归测试服务，不替代真实模型数据。

std::array<Point, 21> make_test_hand(const std::array<bool, 5>& extended) {
    std::array<Point, 21> p{};
    p[0] = {0.0f, 0.0f};
    p[1] = {-.30f, -.30f};
    if (extended[0]) {
        p[2] = {-.58f, -.48f};
        p[3] = {-.82f, -.68f};
        p[4] = {-1.02f, -.88f};
    } else {
        p[2] = {-.45f, -.48f};
        p[3] = {-.20f, -.62f};
        p[4] = {.05f, -.55f};
    }
    constexpr float xs[4] = {-.36f, -.12f, .14f, .38f};
    constexpr float lengths[4] = {1.55f, 1.72f, 1.55f, 1.34f};
    for (int finger = 0; finger < 4; ++finger) {
        const int base = 5 + finger * 4;
        const float x = xs[finger];
        p[base] = {x, -.55f};
        if (extended[finger + 1]) {
            p[base + 1] = {x, -.55f - lengths[finger] * .36f};
            p[base + 2] = {x, -.55f - lengths[finger] * .68f};
            p[base + 3] = {x, -.55f - lengths[finger]};
        } else {
            p[base + 1] = {x, -1.00f};
            p[base + 2] = {x + .24f, -.78f};
            p[base + 3] = {x + .16f, -.48f};
        }
    }
    return p;
}

```cpp
bool self_test() {
    const std::array<std::pair<std::array<bool, 5>, GestureId>, 4> cases{{
        {{{true, true, true, true, true}}, GestureId::OPEN_PALM},
        {{{false, false, false, false, false}}, GestureId::FIST},
        {{{false, true, false, false, false}}, GestureId::POINT},
        {{{false, true, true, false, false}}, GestureId::V_SIGN},
    }};
    for (const auto& item : cases) {
        if (classify_points(make_test_hand(item.first), .99f).id != item.second)
            return false;
    }

    GestureStateMachine machine;
    GestureSnapshot snapshot;
    for (int i = 0; i < 4; ++i) {
        snapshot = machine.update(
            true, {GestureId::OPEN_PALM, .90f}, 1000000u + i * 50000u);
    }
    if (snapshot.state != GestureState::CANDIDATE ||
        snapshot.active_id != GestureId::UNKNOWN) return false;
    snapshot = machine.update(
        true, {GestureId::OPEN_PALM, .90f}, 1200000u);
    if (snapshot.state != GestureState::ACTIVE ||
        snapshot.active_id != GestureId::OPEN_PALM) return false;
    snapshot = machine.update(
        true, {GestureId::OPEN_PALM, .70f}, 1250000u);
    if (snapshot.state != GestureState::RELEASED ||
        snapshot.active_id != GestureId::UNKNOWN) return false;
    snapshot = machine.update(
        true, {GestureId::FIST, .90f}, 1400000u);
    if (snapshot.state != GestureState::RELEASED) return false;
    snapshot = machine.update(false, {}, 1600000u);
    if (snapshot.state != GestureState::NO_HAND) return false;

    GestureStateMachine timeout_machine;
    for (int i = 0; i < 5; ++i) {
        snapshot = timeout_machine.update(
            true, {GestureId::POINT, .90f}, 2000000u + i * 50000u);
    }
    if (snapshot.state != GestureState::ACTIVE) return false;
    snapshot = timeout_machine.update(
        true, {GestureId::POINT, .90f}, 2500001u);
    return snapshot.state == GestureState::RELEASED &&
           snapshot.active_id == GestureId::UNKNOWN;
}
```

## 先理解标签与统计，再运行评估脚本

> **当前位置：`板端已经产生含手势字段的JSONL → [人工真值与自动统计] → 下一篇只接ACTIVE`**

### CSV 标签不是训练集

CSV 是用逗号分隔的表格。本项目标签三列：

```csv
start_sequence,end_sequence,expected_gesture
100,199,OPEN_PALM
250,349,FIST
400,499,POINT
550,649,V_SIGN
```

含义是“操作者确认序号 100～199 实际在做张掌”。它用于验收，不会训练或修改模型。未覆盖的序号按 `UNKNOWN` 处理，因此无手和过渡动作区也能统计误触发。

**混淆矩阵**是“真实类别 × 系统 ACTIVE 类别”的计数表。理想计数集中在对角线；例如真实 POINT 却 ACTIVE 为 V_SIGN，会落在错误格。

**进入延迟**从标签区间第一条有时间戳记录，到第一次出现同名 ACTIVE 的时间差。它包含 5 帧/150 ms 安全确认，因此不应该追求 0。

**误触发**是人工期望 UNKNOWN 的序号里出现非 UNKNOWN ACTIVE。它直接暴露背景、过渡动作或错误残留。

### 评估脚本的函数依赖顺序

```text
load_labels(path) → 读取并验证CSV
expected_at(labels, sequence) → 查一个序号的人工期望
evaluate(labels, records) → 统计混淆、延迟、误触发
main() → 解析路径、读取JSONL、调用前三者并输出JSON
```

下面是完整 `Linux/RK3568/s7_5/evaluate_results.py`。代码已按“辅助函数先定义，main 最后调用”的顺序组织：

```python
#!/usr/bin/env python3
import argparse
import csv
import json
from collections import Counter
from pathlib import Path

GESTURES = ("UNKNOWN", "OPEN_PALM", "FIST", "POINT", "V_SIGN")


def load_labels(path):
    """读取CSV并拒绝未知类别或反向区间。"""
    with path.open(newline="", encoding="utf-8") as stream:
        rows = list(csv.DictReader(stream))
    labels = []
    for row in rows:
        expected = row["expected_gesture"].strip().upper()
        if expected not in GESTURES:
            raise ValueError(f"unsupported gesture: {expected}")
        start = int(row["start_sequence"])
        end = int(row["end_sequence"])
        if start > end:
            raise ValueError(f"invalid sequence range: {start}..{end}")
        labels.append((start, end, expected))
    return labels


def expected_at(labels, sequence):
    """返回该序号的唯一人工标签；未标注时返回UNKNOWN。"""
    matches = [expected for start, end, expected in labels
               if start <= sequence <= end]
    if len(matches) > 1:
        raise ValueError(f"overlapping labels at sequence {sequence}")
    return matches[0] if matches else "UNKNOWN"


def evaluate(labels, records):
    """统计ACTIVE混淆矩阵、进入延迟和UNKNOWN区误触发。"""
    confusion = Counter()
    false_triggers = []
    for record in records:
        sequence = int(record.get("sequence", record.get("frame_index", 0)))
        expected = expected_at(labels, sequence)
        predicted = record.get("active_gesture_name", "UNKNOWN")
        if predicted not in GESTURES:
            predicted = "UNKNOWN"
        confusion[expected, predicted] += 1
        if expected == "UNKNOWN" and predicted != "UNKNOWN":
            false_triggers.append(sequence)

    delays_ms = []
    for start_sequence, end_sequence, gesture in labels:
        if gesture == "UNKNOWN":
            continue
        segment = [record for record in records
                   if start_sequence <= int(record.get(
                       "sequence", record.get("frame_index", 0))) <= end_sequence
                   and record.get("capture_timestamp_us") is not None]
        first = int(segment[0]["capture_timestamp_us"]) if segment else None
        active = next((int(record["capture_timestamp_us"])
                       for record in segment
                       if record.get("active_gesture_name") == gesture), None)
        delays_ms.append({
            "start_sequence": start_sequence,
            "end_sequence": end_sequence,
            "expected_gesture": gesture,
            "delay_ms": None if first is None or active is None
                        else (active - first) / 1000.0,
        })
    return confusion, delays_ms, false_triggers


def main():
    """解析两个输入文件，调用已经定义的函数并输出摘要JSON。"""
    parser = argparse.ArgumentParser()
    parser.add_argument("labels", type=Path)
    parser.add_argument("results", type=Path)
    args = parser.parse_args()

    labels = load_labels(args.labels)
    with args.results.open(encoding="utf-8") as stream:
        records = [json.loads(line) for line in stream if line.strip()]

    confusion, delays, false_triggers = evaluate(labels, records)
    summary = {
        "gestures": list(GESTURES),
        "confusion": {
            expected: {
                predicted: confusion[expected, predicted]
                for predicted in GESTURES
            }
            for expected in GESTURES
        },
        "entry_delay_ms": delays,
        "false_trigger_count": len(false_triggers),
        "false_trigger_sequences": false_triggers,
    }
    print(json.dumps(summary, ensure_ascii=False, indent=2))


if __name__ == "__main__":
    main()
```

首次出现的 Python 写法：

- `csv.DictReader` 用首行列名把每行变成字典。
- `Counter` 对 `(expected,predicted)` 二元键计数。
- `record.get("a", fallback)` 在字段缺失时使用后备值。
- `next((生成器), None)` 找到区间内第一条同名 ACTIVE；找不到返回 `None`。
- `None` 输出 JSON 时成为 `null`，表示该区间从未进入正确 ACTIVE，不等于 0 ms。
- `if __name__ == "__main__"` 保证脚本被导入时不会自动运行命令行入口。

具体走读：标签 100～199 是 OPEN_PALM。序号 100～103 的 `active_gesture_name` 都是 UNKNOWN，序号 104 首次为 OPEN_PALM；若采集时间从 5,000,000 us 到 5,200,000 us，进入延迟是 200 ms。若序号 220 未被标签覆盖却 ACTIVE 为 POINT，误触发列表加入 220。

## 验证闭环和典型故障定位

> **当前位置：`逻辑、板端入口、评价方法都已建立 → [证明可靠手势] → S7.6输入`**

| 层级 | 正常结果 | 失败现象 | 第一检查点 | 能证明什么 |
|---|---|---|---|---|
| 几何自检 | 文字 `self-test ok`、退出码0 | 退出码1 | 最近改动的点编号、分数和门槛 | 合成手形规则一致；不证明真人准确 |
| 单帧观察 | 正确手势多为最高分，模糊时 UNKNOWN | 长期全 UNKNOWN 或类别乱跳 | 标注骨架、五指伸展度、presence | 分类输入和几何规则 |
| 候选确认 | 前4帧不ACTIVE，第5帧且时间满足后ACTIVE | 第1帧就ACTIVE | JSONL 的 candidate_frames 和时间戳 | 防单帧误触发 |
| 立即释放 | 无手、低置信度、切换、超时同帧清 active | 旧 active 残留 | hand_valid、confidence、帧间隔 | 失效不会保持旧动作 |
| 冷却 | 300 ms 内不重激活 | 快速反复激活 | release 时间线 | 防抖，不是保持旧动作 |
| 真人统计 | 对角线占主要、UNKNOWN区无异常ACTIVE | 混淆/误触发/延迟异常 | 原始 JSONL 与标签区间 | 当前场景的实际表现 |

真人验收至少要让四类各重复 10 次，并覆盖无手、半握、遮挡、画面边缘、左右手、远近、角度和快速切换。若换摄像头安装、模型、阈值或手势定义，旧统计不能自动沿用。

## 迁移练习：只改变确认帧数

在一个实验分支把 `kConfirmFrames` 从 5 改为 6，其他值不动，先运行纯逻辑自检并相应更新测试期望，再对同一份固定 JSONL 做离线重放。预测：误触发机会可能下降，进入延迟通常上升。不要同时改置信度和冷却，否则无法判断是哪一个条件造成变化。实验结束后不要把旧真人验收标记套到新门槛。

## 文字复盘与最终结构图

你现在能区分三层概念：关键点是测量；`GestureObservation` 是单帧判断；`GestureSnapshot` 是跨帧安全状态。分类器先把关节直线度、伸展距离和指尖分离度组合成四类得分，再用最低分、第一/第二名差值和 presence 共同拒绝模糊输入。

状态机要求同一高置信度手势同时满足 5 帧和 150 ms 才 ACTIVE；无手、未知、低置信度、类别切换或 250 ms 输入空洞都立即清空活动手势；300 ms 冷却只阻止新动作重入，不延长旧动作。

```text
21×3关键点 + presence
  ↓ 有限值/掌宽检查
Point[21]
  ↓ distance + straightness
五指extension[5]
  ↓ 四类几何得分 + 第一/第二名差值
GestureObservation{id, confidence}
  ↓ hand_valid + 单调时间
GestureStateMachine
  ├─ NO_HAND
  ├─ UNKNOWN
  ├─ CANDIDATE：>=5帧且>=150ms
  ├─ ACTIVE：唯一允许active_id非0
  └─ RELEASED：立即清零，冷却300ms
  ↓
GestureSnapshot
  ↓
下一篇：把ACTIVE手势映射成有边界、可校验的虚拟RC帧
```
