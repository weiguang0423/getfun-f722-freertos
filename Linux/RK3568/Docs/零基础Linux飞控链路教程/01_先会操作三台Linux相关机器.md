## 终端、Shell、命令和参数不是同一个东西

> **当前位置：`只会打开 Windows 程序 → [理解一行命令由谁接收] → 学习路径`**
>
> 本节只建立命令执行模型。完成后，你能把一行文字拆成“程序名”和“参数”，而不是把整行看成咒语。

### 终端是显示和输入的窗口

先把终端理解成一个文字窗口。你在里面输入一行文字，按回车，然后看到输出。

Windows Terminal、PowerShell 窗口、PuTTY 串口窗口都可以是终端。终端本身不决定 `ls` 或 `Get-Location` 是什么意思。

### Shell 是读取命令行的程序

Shell 负责读取你输入的文字，拆分程序名和参数，然后启动程序。

在本项目中会遇到两类 Shell：

| Shell | 常见地点 | 命令风格 |
|---|---|---|
| PowerShell | Windows | `Get-Location`、`Set-Location` |
| `sh` 或 `bash` | WSL、RK3568 Linux | `pwd`、`cd`、`ls` |

同一个终端窗口可以启动另一个 Shell。比如你在 PowerShell 中输入 `wsl` 后，窗口没有消失，但后续命令已经交给 WSL 中的 Linux Shell。

### 一行命令怎样被拆开

先看一个不执行的结构：

```text
程序名    参数1      参数2
  ls      -l       /dev/video0
```

- `ls` 是要启动的程序名，作用是列出文件。
- `-l` 是选项，要求显示详细信息。
- `/dev/video0` 是操作对象，也就是要查看的路径。

空格把它们分开。文件名里若包含空格，需要用引号把完整路径包起来；否则 Shell 会误以为是多个参数。

例如 Windows 路径：

```text
D:\My Project\file.md
```

在 PowerShell 参数中应写成：

```powershell
'D:\My Project\file.md'
```

单引号告诉 PowerShell：“里面的空格属于路径，不是参数分隔符。”

## Linux 怎样组织文件和目录

> **当前位置：`知道命令由 Shell 解释 → [建立 Linux 路径模型] → 在 WSL 中定位仓库`**
>
> 本节只讲路径，不运行项目程序。完成后，你能解释绝对路径、相对路径、当前目录和 WSL 的 `/mnt/e`。

### 文件和目录

普通文件保存一串字节。源代码、模型、图片和可执行程序本质上都由字节组成，只是内容和用途不同。

目录保存名字到文件/子目录的组织关系。目录可以理解成文件夹，但 Linux 把目录也作为一种特殊文件处理。

### Linux 只有一棵目录树

Windows 常用盘符区分磁盘：

```text
C:\
D:\
E:\
```

Linux 从一个根目录开始：

```text
/
```

根目录下面有 `home`、`dev`、`tmp` 等子目录：

```text
/
├── home
├── dev
├── tmp
└── ...
```

Linux 使用正斜杠 `/` 分隔路径。Windows 通常使用反斜杠 `\`。

### 绝对路径与相对路径

从根目录 `/` 开始写出的完整路径叫绝对路径：

```text
/home/user123/rk3568_sdk
```

它不依赖你当前站在哪个目录。

不以 `/` 开头的路径叫相对路径：

```text
Linux/RK3568/s7_4
```

Shell 会从“当前目录”开始寻找它。如果当前目录不是仓库根目录，相同相对路径就可能找不到。

`.` 表示当前目录，`..` 表示上一级目录。例如：

```text
./s7_4_live
../s7_3/s7_3_board_infer.cpp
```

第一行表示“当前目录中的 `s7_4_live`”。第二行表示“先回到上一级，再进入 `s7_3`”。

### WSL 怎样看到 Windows 的 E 盘

WSL 把 Windows 磁盘挂载到 `/mnt` 下面。因此 Windows 路径：

```text
E:\getfun-f722-freertos\GETFUN_F722_FreeRTOS
```

在 WSL 中通常对应：

```text
/mnt/e/getfun-f722-freertos/GETFUN_F722_FreeRTOS
```

这里的 `mnt` 来自 mount，意思是“挂载”。当前只需要知道它把 Windows 的 E 盘接入 Linux 目录树；挂载机制的内核细节不影响本课程。

## 第一次进入 WSL 并确认“我在哪里”

> **当前位置：`理解了路径 → [从 PowerShell 进入 WSL 并定位仓库] → 认识文件类型`**
>
> 本节第一次实际执行命令。每条命令都会在使用前说明来源、输入、输出和失败含义。

### 先用 PowerShell 查看当前位置

PowerShell 内置命令 `Get-Location` 的名字可以拆成“获取位置”。它没有必需参数，输出当前 PowerShell 目录。

**运行地点：Windows PowerShell。**

```powershell
Get-Location
```

具体走读：如果输出是：

```text
Path
----
E:\getfun-f722-freertos\GETFUN_F722_FreeRTOS
```

说明 PowerShell 当前站在仓库根目录。它只确认 Windows 当前目录，不说明 WSL 当前目录。

### 检查 WSL 是否存在

`wsl.exe` 是 Windows 提供的 WSL 管理入口。参数 `--status` 表示只查询状态，不启动项目程序、不修改设置。

**运行地点：Windows PowerShell。**

```powershell
wsl --status
```

正常时会显示默认 WSL 发行版或版本信息。若出现“无法将 wsl 识别为命令”，说明当前系统没有可用的 WSL 命令，后面的 WSL 操作不能继续。

### 启动默认 WSL

不带参数运行 `wsl`，Windows 会进入默认 Linux 发行版。

**运行地点：Windows PowerShell。**

```powershell
wsl
```

成功后提示符可能变成：

```text
user123@DESKTOP-LU363IJ:~$
```

提示符里的信息不是命令：

- `user123` 是当前 Linux 用户名；
- `DESKTOP-LU363IJ` 是主机名；
- `~` 表示当前位于这个用户的家目录；
- `$` 常表示普通用户 Shell；板端 root 用户常显示 `#`。

### 用 `pwd` 查询 WSL 当前目录

`pwd` 是 print working directory 的缩写，中文是“打印当前工作目录”。它没有必需参数，输出一个绝对路径。

**运行地点：已经进入的 WSL Shell。**

```sh
pwd
```

若输出：

```text
/home/user123
```

表示当前目录是 WSL 用户 `user123` 的家目录。它不是 Windows 仓库。

### 用 `cd` 进入仓库

`cd` 是 change directory 的缩写，中文是“改变当前目录”。它接收一个目标目录，没有普通成功输出；成功后 Shell 的当前目录改变。

**运行地点：WSL。**

```sh
cd /mnt/e/getfun-f722-freertos/GETFUN_F722_FreeRTOS
```

这条命令的输入是仓库绝对路径。它不复制文件，不修改文件。

因为 `cd` 成功时通常什么也不打印，所以必须用已经学过的 `pwd` 验证：

```sh
pwd
```

预期输出：

```text
/mnt/e/getfun-f722-freertos/GETFUN_F722_FreeRTOS
```

若 `cd` 报 `No such file or directory`，第一个检查点是 Windows 仓库真实盘符和目录名。不要在路径未知时继续运行构建脚本。

## 怎样安全地查看目录和文件

> **当前位置：`已经进入 WSL 仓库 → [区分目录、普通文件和设备文件] → 认识程序与权限`**
>
> 本节只使用读取命令。完成后，你能查看文件类型和少量文本，而不会误改项目。

### `ls`：列出目录条目

`ls` 来自 list，作用是列出目录中的名字。选项 `-l` 表示 long format，即详细格式。

先查看 RK3568 目录：

**运行地点：WSL；当前目录必须是仓库根目录。**

```sh
ls -l Linux/RK3568
```

你会看到类似：

```text
drwxr-xr-x ... s7_4
-rw-r--r-- ... README.md
```

最左侧第一个字符表示类型：

- `d` 表示目录；
- `-` 表示普通文件；
- `l` 表示符号链接，类似“指向另一个路径的入口”；
- `c` 或 `b` 常见于设备文件。

`ls` 成功只证明目录可读取，不证明其中程序能编译或运行。

### `cat`：把小文本文件内容送到标准输出

`cat` 原意是 concatenate，能够连接并输出文件。在本课程中先只用它显示较短文本文件。

它接收文件路径，把文件字节写到“标准输出”，默认显示在终端。

**运行地点：WSL；当前目录为仓库根目录。**

```sh
cat Linux/RK3568/s7_2/README.md
```

这条命令不会修改 README。若对很大的二进制程序使用 `cat`，终端会出现乱码；因此只对确认是文本且较短的文件使用。

### `file`：根据内容判断文件类型

`file` 是一个检查程序。它读取目标文件的开头和结构，告诉你文件大致属于文本、图片、脚本或 ELF 可执行文件。

当前仓库中存在板端二进制 `s7_4_live`。在执行它之前，先查看类型：

**运行地点：WSL；当前目录为仓库根目录。**

```sh
file Linux/RK3568/s7_4/s7_4_live
```

历史构建产物的预期关键信息是：

```text
ELF 64-bit ... ARM aarch64 ...
```

`ELF` 是 Linux 常见可执行文件格式。AArch64 表示这个程序面向 RK3568，而不是当前 x86-64 WSL。

这一步只读文件。它证明“文件格式和目标架构”，不证明板端依赖库、摄像头或 NPU 可以运行。

## 程序、进程和 PID

> **当前位置：`能查看文件 → [理解程序运行后发生什么] → 观察输出和退出码`**
>
> 本节建立后文稳定性脚本依赖的进程概念，但暂时不启动摄像头程序。

### 程序是磁盘上的文件

`s7_4_live` 静静放在目录里时，它只是一个可执行文件。它有字节内容、文件大小和权限，但没有正在使用 CPU。

### 进程是程序的一次运行实例

当操作系统启动一个程序，会创建一个进程。进程拥有：

- 一个进程编号；
- 自己的内存；
- 打开的文件；
- 当前运行状态；
- 正常结束或失败结束的结果。

同一个程序可以同时启动多次，每次都是不同进程。

### PID 是进程编号

PID 是 Process ID 的缩写，中文是“进程标识号”。后文脚本执行 `PID=$!`，就是保存刚刚启动的后台进程编号，以便读取它的内存、文件描述符和结束状态。

现在先用 `ps` 观察当前 Shell 相关进程。外部命令 `ps` 是 process status 的缩写。选项 `-f` 要求显示较完整字段。

**运行地点：WSL。**

```sh
ps -f
```

输出中的 `PID` 列是每个进程的编号，`CMD` 列是启动命令。你至少会看到当前 Shell 和 `ps -f` 自身。

本次观察确认了“命令运行会成为进程”。下一篇的构建工具和后文的摄像头程序都会遵守同一模型。

## 标准输出、错误输出和退出码

> **当前位置：`知道程序会成为进程 → [理解进程怎样交出结果] → 理解权限和脚本运行方式`**
>
> 本节建立后文所有日志文件的基础。完成后，你能区分程序打印的内容和程序是否成功。

### 三条标准数据通道

进程启动时通常会获得三条标准通道：

| 编号 | 名称 | 当前用途 |
|---:|---|---|
| 0 | 标准输入 stdin | 从键盘或文件读取数据 |
| 1 | 标准输出 stdout | 输出正常结果 |
| 2 | 标准错误 stderr | 输出诊断和错误 |

默认情况下，标准输出和标准错误都显示在终端，所以肉眼看起来混在一起。后文会用 `>` 和 `2>` 把它们保存到不同文件。

### 退出码说明程序怎样结束

每个进程结束时都会向父 Shell 交出一个整数。按照 Linux 常见约定：

- `0` 表示程序认为本次操作成功；
- 非 `0` 表示失败或特殊结束；
- 具体非零含义由程序定义。

Shell 用特殊名字 `$?` 保存“上一条命令”的退出码。`$` 表示取变量值，`?` 是这个特殊变量的名字。

先运行已经解释过的 `pwd`，然后立即查看退出码。Shell 内置命令 `printf` 用格式字符串输出文字；`%s` 表示把后面的值放进这里，`\n` 表示换行。

**运行地点：WSL。**

```sh
pwd
printf '上一条命令的退出码：%s\n' "$?"
```

若 `pwd` 成功，第二行预期显示：

```text
上一条命令的退出码：0
```

注意顺序：必须紧跟在要检查的命令后读取 `$?`。如果中间运行另一条命令，`$?` 就会被新命令替换。

### 制造一个无破坏的失败来观察证据

我们需要一个不会修改文件的失败。让 `ls` 查看一个明确不存在的路径即可。

在执行前先预测：

- 标准输出没有目录内容；
- 标准错误出现 `No such file or directory`；
- 退出码非 0。

**运行地点：WSL。**

```sh
ls /this_path_is_intentionally_missing
printf '上一条命令的退出码：%s\n' "$?"
```

这次失败不是需要修复的故障，而是为了认识三种证据：错误文字、退出码以及没有正常数据。

## 为什么脚本有时用 `sh script.sh`，有时用 `./program`

> **当前位置：`能解释进程输出和退出码 → [理解权限与解释器] → 登录 RK3568`**
>
> 本节解决常见的 `Permission denied` 和“为什么要写 `./`”。完成后，你不会用盲目修改权限的方式解决所有运行失败。

### Linux 文件权限的三组对象

`ls -l` 输出开头可能是：

```text
-rwxr-xr-x
```

第一个字符是文件类型。后面九个字符分三组：

```text
rwx   r-x   r-x
所有者  同组用户  其他用户
```

- `r` 是 read，允许读取；
- `w` 是 write，允许修改；
- `x` 是 execute，允许作为程序直接执行；
- `-` 表示没有该权限。

### `sh script.sh` 是让解释器读取脚本

当你执行：

```text
sh Linux/RK3568/s7_4/precheck_wsl.sh
```

真正启动的程序是 `sh`。脚本路径作为参数交给 `sh` 读取，所以脚本本身只要可读，不一定需要执行位。

### `./program` 是直接运行当前目录里的可执行文件

Linux 默认不会在当前目录自动搜索程序。因此：

```text
./s7_4_live
```

前面的 `./` 明确告诉 Shell：“使用当前目录中的这个文件。”这时文件需要执行权限，而且文件架构必须匹配当前 CPU。

如果在 x86-64 WSL 直接运行 AArch64 的 `s7_4_live`，即使有执行权限，也会出现 `Exec format error`。正确处理不是反复 `chmod`，而是把程序部署到 RK3568。

本课程不会把 `chmod 777` 当成通用修复。它会同时开放过多权限，而且无法修复架构、缺库或文件损坏问题。

## 登录 RK3568 前先理解串口和 SSH

> **当前位置：`WSL 操作基础已经建立 → [进入真正的 RK3568 Linux] → 对比两台 Linux`**
>
> 本节教两种登录路径。串口适合网络未知或启动故障；SSH 适合网络正常时日常复制和操作。

### 串口登录是什么

串口终端把电脑键盘字符通过 USB 转串口设备发送给开发板，开发板再把启动日志和 Shell 输出发回来。它不依赖板端 IP，因此适合第一次确认板子是否启动。

项目历史实测使用：

```text
Windows 端口：COM8
波特率：1500000
数据格式：8N1
```

`8N1` 表示 8 个数据位、无校验位、1 个停止位。COM 号可能因 USB 端口变化而改变；`COM8` 是历史事实，不是永久值。

在 PuTTY 或其他串口工具中选择实际 COM 口和 `1500000 8N1`。如果启动后看到：

```text
debug>
```

这不是 Linux Shell，而是 FIQ 调试入口。输入：

```text
console
```

再回车，回到 Linux 控制台。

登录后常见提示符：

```text
root@ATK-DLRK3568:~#
```

`root` 是 Linux 超级用户。它几乎不受普通文件权限限制，因此误操作破坏范围更大。板端 root Shell 中只运行课程明确标注的命令。

### 在板端确认系统和当前网络地址

`uname` 用于查询内核和机器信息。选项 `-a` 表示显示全部常用字段，`-m` 只显示机器架构。

`ip` 是 Linux 网络配置与查询工具。两个参数 `address show` 表示显示网络接口地址，不修改地址。

**运行地点：RK3568 板端串口 Shell。**

```sh
uname -a
uname -m
ip address show
```

历史板端架构输出应包含：

```text
aarch64
```

`ip address show` 中找到正在使用的有线接口及其 `inet` 地址。历史直连地址曾是 `169.254.151.86/16`，本次以实际输出为准。

### SSH 登录是什么

SSH 是 Secure Shell 的缩写。它通过网络在远程机器上打开加密 Shell。

SSH 命令由三部分组成：

```text
ssh    用户名@目标IP
程序       登录身份和机器地址
```

假设你刚从板端 `ip address show` 确认地址是 `169.254.151.86`，才在 WSL 执行：

**运行地点：WSL。**

```sh
ssh root@169.254.151.86
```

首次连接可能询问是否信任主机指纹。确认 IP 确实属于你的 RK3568 后输入 `yes`。密码输入时终端不显示星号或字符，这是防止旁人看到密码长度的正常行为。

登录成功后，提示符变成板端 root 提示符。此时后续命令在 RK3568 运行，不再在 WSL 运行。

若出现 `Connection timed out`，第一检查点是板端 IP、网线和两端网卡；若出现 `Connection refused`，说明网络到达但板端 SSH 服务可能没有监听；若出现 `Permission denied`，说明认证失败，不是摄像头或 SDK 问题。

### 安全退出远程 Shell

Shell 内置命令 `exit` 会结束当前 Shell。SSH 会随远程 Shell 结束而断开，回到 WSL。

**运行地点：SSH 登录后的 RK3568 Shell。**

```sh
exit
```

退出后观察提示符：应重新出现 WSL 用户和 PC 主机名。提示符变化是判断操作地点的重要证据。

## 用同一组只读命令比较 WSL 和 RK3568

> **当前位置：`已经会进入两台 Linux → [用证据区分它们] → 为构建课程建立起点`**
>
> 本节形成完整验证闭环：同一命令在两台机器上输出不同架构和系统，从而证明运行地点。

先定义本轮要观察的三个对象：

| 对象 | 命令 | 证据 |
|---|---|---|
| 当前目录 | `pwd` | 绝对路径 |
| CPU 架构 | `uname -m` | WSL 通常 x86_64，RK3568 是 aarch64 |
| 系统版本文本 | `cat /etc/os-release` | WSL 发行版与板端 Buildroot 不同 |

这些命令都已经在前文解释过；现在才第一次把它们组合成环境确认流程。

**运行地点：WSL。**

```sh
pwd
uname -m
cat /etc/os-release
```

记录输出后 SSH 登录板端，再运行同一组：

**运行地点：RK3568。**

```sh
pwd
uname -m
cat /etc/os-release
```

具体走读：

- WSL 的 `pwd` 可能是 `/mnt/e/.../GETFUN_F722_FreeRTOS`，板端可能是 `/root` 或 `/userdata`。
- WSL 通常显示 `x86_64`，板端必须显示 `aarch64`。
- WSL 可能显示 Ubuntu，板端记录为 Buildroot。

若三项输出没有差别，很可能你没有真正进入板端，而是在同一 Shell 重复执行。先看提示符和 SSH 返回信息。

## 本篇验证闭环

正常完成后，你应保存或能够复述下面的证据：

| 检查 | 正常观察 | 失败现象 | 第一检查点 |
|---|---|---|---|
| PowerShell 当前目录 | Windows 仓库绝对路径 | 路径不是仓库 | 用 `Get-Location`，不要猜 |
| WSL 启动 | 出现 Linux 用户提示符 | `wsl` 不存在 | Windows WSL 状态 |
| WSL 仓库路径 | `pwd` 为 `/mnt/e/...` | `cd` 报路径不存在 | Windows 盘符和目录名 |
| WSL 架构 | `x86_64` | 与预期不同 | 是否进入了另一台远程机器 |
| RK3568 串口 | 出现板端登录/Shell | 空白或乱码 | COM 号、1500000、线缆和共地 |
| RK3568 架构 | `aarch64` | 不是 ARM64 | 是否连到了正确设备 |
| SSH | 提示符切换到 RK3568 | 超时/拒绝/认证失败 | 分别查网络、服务、账号密码 |
| 退出码 | 成功为 0，故意失败非 0 | 只看文字不看状态 | 命令后立即读取 `$?` |

本轮确认的是“可以安全地进入并区分两个 Linux 环境”。它没有确认 SDK 完整、模型可转换、程序可编译或板端摄像头可用。下一篇会以这个明确起点开始。

## 只改变一个条件的迁移练习

不要执行新的复杂命令。只改变“当前目录”这一个条件，观察相对路径为何依赖位置。

你已经知道：

- `cd` 改变当前目录；
- `pwd` 验证当前目录；
- `ls` 查看给定路径；
- `..` 表示上一级。

在 WSL 仓库根目录先执行：

```sh
pwd
ls Linux/RK3568
```

然后进入 `Linux` 子目录：

```sh
cd Linux
pwd
ls RK3568
```

两次列出的目标是同一个目录，但相对路径从 `Linux/RK3568` 变成 `RK3568`。这说明相对路径必须结合当前目录解释。

最后回到仓库根目录：

```sh
cd ..
pwd
```

只有 `pwd` 再次显示仓库根目录，才进入下一篇。

## 文字复盘和最终结构图

本篇建立的最小 Linux 模型是：

```text
终端窗口
  ↓ 你输入一行文字
Shell
  ↓ 拆成程序名和参数
程序文件
  ↓ 操作系统启动
进程（有 PID、内存、打开文件）
  ├─ 标准输入 0
  ├─ 标准输出 1
  ├─ 标准错误 2
  └─ 结束时返回退出码
```

文件路径决定程序能否找到输入；权限和 CPU 架构决定程序能否启动；输出和退出码提供不同证据。后面的每个脚本都只是把这些基本机制组合起来。
