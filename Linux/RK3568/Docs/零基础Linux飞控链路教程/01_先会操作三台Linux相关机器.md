# 为本项目补上最少的 Linux 基础

这一篇不是通用 Linux 教材。我们只学习后面部署 RK3568 程序时真正会用到的概念。

学完以后，你应该能分清下面几件事：

- 我现在是在 Windows、WSL，还是 RK3568 上；
- 一个路径指向哪里；
- 源码、可执行文件和正在运行的进程有什么区别；
- `/dev/video0` 和 `/dev/tty*` 为什么看起来像文件；
- 怎样把程序复制到开发板，再从电脑登录开发板；
- 程序没有运行时，应该先看哪一类证据。

## 先分清三个操作环境

后面的工作会在三个地方进行。很多初学者遇到的问题，不是命令本身错了，而是在错误的地方运行了它。

### Windows PowerShell

这是 Windows 的命令窗口。项目原件在：

```text
E:\getfun-f722-freertos\GETFUN_F722_FreeRTOS
```

看到 `E:\...>` 这类提示时，你在 Windows，不是在 Linux。

### WSL 终端

WSL 里同一个 E 盘会出现在：

```text
/mnt/e/getfun-f722-freertos/GETFUN_F722_FreeRTOS
```

Linux 使用 `/` 分隔目录，Windows 使用 `\`。同一批文件，因为操作系统不同，会看到两种写法。

### RK3568 板端终端

通过调试串口或 SSH 登录开发板以后，你操作的是板端 Linux。这里能看到摄像头设备、NPU 运行库和部署后的 ARM64 程序。

一个很实用的习惯是：每次准备做重要操作前，先确认“我是谁、我在哪台机器、当前目录是什么”。这样能避免把板端命令跑到 WSL，也能避免把 x86-64 程序误传到 RK3568。

## 终端和 Shell 是什么

终端是你看到的文字窗口。Shell 是窗口里负责读取命令并启动程序的那一层。

你输入：

```text
file s7_6_live
```

Shell 会把它理解成两部分：

- `file`：要启动的程序；
- `s7_6_live`：交给这个程序检查的文件。

本教程不会教 Shell 编程。你只需要知道：一行命令通常由“程序名”和“参数”组成，空格用来分开它们。

## Linux 用一棵目录树保存所有东西

Linux 最顶层的目录是 `/`。其他目录都从它向下展开。

本项目常见的路径有：

| 路径 | 在本项目中的含义 |
|---|---|
| `/mnt/e/...` | WSL 访问 Windows E 盘 |
| `/home/用户名` | WSL 某个用户自己的目录 |
| `/userdata/...` | RK3568 上常用的部署位置 |
| `/dev/video0` | 摄像头采集设备入口 |
| `/dev/tty*` | 串口设备入口 |
| `/usr/lib` | 板端常见的系统动态库目录 |

### 绝对路径和相对路径

以 `/` 开头的是绝对路径。它从整棵目录树的根开始，所以不依赖当前目录。

不以 `/` 开头的是相对路径。它从你当前所在目录开始解释。

例如，你当前在：

```text
/userdata/gesture_rc
```

那么 `./s7_6_live` 就是：

```text
/userdata/gesture_rc/s7_6_live
```

这里的 `.` 表示当前目录。

### 为什么路径错了会出现很多不同问题

如果程序提示“文件不存在”，不一定真的是程序坏了。可能只是：

- 当前目录不对；
- 使用了相对路径，但相对的起点不是你想的目录；
- WSL 路径和 Windows 路径混用了；
- 文件只存在于电脑，还没有复制到 RK3568；
- 大小写不一致。Linux 通常区分大小写。

所以看到 `No such file or directory` 时，第一反应应该是确认路径，而不是立刻重装环境。

## 只需要掌握几个查看命令

这些是直接查看系统状态的命令，不是脚本。

### `pwd`：我现在在哪个目录

`pwd` 会显示当前目录的完整路径。准备运行程序前先看一次，能避免大量路径问题。

### `ls`：当前目录里有什么

`ls` 列出文件和子目录。`ls -l` 还会显示大小、权限和修改时间。

### `cd`：切换当前目录

`cd /userdata/gesture_rc` 表示进入板端部署目录。成功时通常没有额外输出；再次执行 `pwd` 可以确认结果。

### `file`：这个文件到底是什么

`file` 不运行目标，只查看它的格式。

对于 RK3568 程序，理想结果应包含：

```text
ELF 64-bit ... ARM aarch64
```

如果显示 `x86-64`，说明它是给电脑用的，RK3568 不能运行。

### `ldd`：程序启动时要找哪些动态库

一个程序不一定把所有功能都装在自己文件里。它可能在启动时加载 OpenCV 和 RKNN Runtime 等动态库。

`ldd ./s7_6_live` 会列出这些依赖。出现 `not found` 时，意思通常不是程序本身不存在，而是它需要的某个动态库没有找到。

## 文件、程序和进程不是一回事

### 文件

文件是磁盘上保存的数据。源码、模型、图片、动态库和可执行程序都是文件。

### 程序

程序通常指包含机器指令的可执行文件，例如 `s7_6_live`。它还没有运行，只是保存在磁盘上。

### 进程

当 Linux 开始执行这个程序时，系统会创建一个进程。进程有自己的内存、打开的设备和运行状态。

同一个程序可以运行两次，从而产生两个不同进程。每个进程都有一个编号，叫 PID，也就是 Process ID。

这个区别对排错很重要：

- 文件存在，不代表进程已经启动；
- 进程启动，不代表摄像头已经打开成功；
- 进程还活着，也不代表它正在产生有效手势；
- 进程退出后，磁盘上的程序文件仍然存在。

### 怎样看进程

`ps` 用来查看进程。项目程序没有输出时，可以先确认它是否还在运行。

`kill PID` 是向指定进程发送结束请求。它不是删除程序文件。结束进程以后，可执行文件仍在原位置。

## 标准输出和错误输出为什么要分开

Linux 程序通常有两条文字输出通道：

- 标准输出：正常结果，例如逐帧 JSONL；
- 标准错误：诊断信息，例如设备打不开、模型加载失败。

这两类内容最好分开理解。正常结果回答“程序处理出了什么”，错误输出回答“程序为什么没法继续”。

如果把两者混在一起，后面就很难自动解析逐帧记录。这也是项目把结果记录和诊断日志分开的原因。

## 退出码是什么

进程结束时会交给 Shell 一个整数，叫退出码。

通常：

- 0 表示程序按预期完成；
- 非 0 表示程序遇到错误或主动判定失败。

但退出码只能说明“程序怎样结束”，不能证明硬件效果。例如摄像头程序返回 0，最多说明软件没有报告失败；它不能单独证明画面正确、关键点准确或者串口电平正常。

## `/dev/video0` 为什么也叫文件

Linux 把很多硬件入口也放进文件系统。`/dev/video0` 不是一段普通录像，而是内核提供给程序的摄像头接口。

程序对它执行“打开、设置格式、申请缓冲、取一帧”等操作，内核再把这些请求转给摄像头驱动。

串口设备 `/dev/tty*` 也是同样思路。程序像写文件一样写入字节，内核再把字节交给 UART 硬件发出去。

这种设计的好处是程序可以使用相似的“打开、读取、写入、关闭”方式操作不同设备。它们看起来像文件，但背后连接的是驱动和硬件。

## 权限为什么会阻止设备访问

Linux 会记录谁可以读、写或执行一个文件。

对于本项目，常见现象有：

- 程序文件没有执行权限，启动时报 `Permission denied`；
- 当前用户无权打开 `/dev/video0`；
- 当前用户无权写串口设备；
- 文件能读取，但所在目录不允许访问。

权限错误和文件不存在是两类问题。看到 `Permission denied` 时，先检查访问权限和当前用户，不要把它当成路径错误。

## SSH 和串口登录有什么区别

### 调试串口登录

调试串口通过 USB 转串口连接电脑。它不依赖网络，适合第一次确认板子是否启动、查看启动日志和配置网络。

注意：开发板的调试串口波特率，不等于后面 RK3568 向 F722 发送虚拟 RC 的 115200。它们是两条不同用途的串口链路。

### SSH 登录

SSH 通过网络打开 RK3568 上的远程 Shell。它适合日常复制文件、启动程序和查看日志。

概念上，它做的是：

```text
电脑上的终端
  ↓ 网络加密连接
RK3568 上的 Shell
```

登录以后，你输入的 Linux 命令是在 RK3568 上执行，不是在电脑上执行。

## `scp` 是怎样复制文件的

`scp` 使用 SSH 连接复制文件。

从 WSL 把 ARM64 程序复制到 RK3568，实际发生的是：

```text
WSL 中的程序文件
  ↓ 网络
RK3568 的部署目录
```

复制完成只证明目标目录出现了一个文件。还需要继续确认：

- 文件大小和哈希是否一致；
- `file` 是否显示 ARM aarch64；
- 动态库是否齐全；
- 程序是否能打开摄像头和模型；
- 串口设备名是否对应真实引脚。

## 遇到问题时按什么顺序看

不要一上来就怀疑模型或飞控。先从最靠前、最容易确认的地方开始。

| 现象 | 先确认什么 |
|---|---|
| 找不到文件 | 当前机器、`pwd`、路径和大小写 |
| Permission denied | 当前用户和文件/设备权限 |
| Exec format error | `file` 是否显示 ARM aarch64 |
| 程序启动后立刻退出 | 错误输出和退出码 |
| 动态库 not found | `ldd` 和部署目录里的库 |
| 摄像头打不开 | `/dev/video0` 是否存在、是否被占用 |
| 串口打不开 | `/dev/tty*` 设备名、权限和占用情况 |
| 进程存在但没有有效结果 | 摄像头帧、模型输出和逐帧状态，而不是只看 `ps` |

## 这一篇真正要记住的内容

不需要背命令。你真正要建立的是这几个判断：

1. 先确认自己在哪台机器上。
2. 路径决定程序去哪里找文件。
3. 文件存在、程序能启动、进程正在运行、功能正常，是四个不同层次。
4. `/dev/video0` 和 `/dev/tty*` 是 Linux 暴露硬件的入口。
5. 错误输出、退出码和实际硬件现象分别提供不同证据。
